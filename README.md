# 온이음 워크스페이스

## 서비스 주소 : [https://on-ieum.vercel.app/](https://on-ieum.vercel.app/)

**담당자가 바뀌어도, 업무는 이어집니다.**

온이음은 업무의 기준과 절차를 미리 정리하고 수행 기록을 축적해, 인수인계를 일상에서 준비하는 AI 기반 업무관리 플랫폼입니다. AI가 문서를 바탕으로 업무 초안을 만들고, 담당자가 검토해 등록한 업무에 일정과 수행 기록이 쌓입니다. 후임자는 이 맥락을 이어받아 업무를 계속할 수 있습니다.

현재 버전은 **1.0.3**이며, 가상 조직과 계정으로 업무 흐름을 체험할 수 있는 프로토타입입니다.

## 주요 기능

| 기능 | 무엇을 할 수 있나요? | 사용하는 화면 |
| --- | --- | --- |
| **① AI 업무등록** | 인수인계서·지침·계획서 등의 파일과 설명으로 단위업무·세부업무 초안을 구성하고, 담당자가 검토한 뒤 등록합니다. | **개인업무 → AI 업무등록** |
| **② AI 업무 설명·절차도** | 업무 개요·첨부파일과 선택한 법령·근거로 설명과 수행 절차 초안을 만듭니다. AI의 인용문구는 원문과 자동 대조하며, 담당자가 내용과 순서를 확인해 적용합니다. | 세부업무의 **업무 개요 / 관련 근거 / 절차** |
| **③ 일정·수행 관리** | 절차별 날짜와 진행률을 확인하고, 반복 업무의 회차별 수행 결과를 남깁니다. 부서장은 소속 부서의 진행 현황을 확인합니다. | **일정·수행 / 업무 일정 / 부서 업무 관리** |
| **④ 끊김 없는 인수인계** | 업무 전체 또는 일부를 선택해 인계를 요청합니다. 부서장이 승인하면 후임자가 진행 중인 일정과 수행 기록까지 이어받습니다. | **인수인계** |
| **⑤ 조직 협업·성과 관리** | 여러 부서에 공통업무의 절차·기한을 배포하고 진행 현황을 확인합니다. 지시사항 월별 실적, 반기 성과 제출·평가, 업무분장표와 예산 집계도 지원합니다. | **공통업무 · 지시사항 / 성과 · 평가 / 업무분장표** 등 |

## 실행 및 작동 방법

### 빠른 시작

**서비스를 체험하려면 별도 설치 없이 위 서비스 주소에 접속하세요.**

1. **접근 코드 확인**이 표시되면 안내받은 **숫자 8자리 코드**를 입력합니다.
2. **업무 담당자 1**을 선택하고 **데이터정보화담당관실 · 송주무관**인지 확인한 뒤 시작합니다.
3. 로그인 후 **업무 홈**에서 현재 할 일을 확인하고, 왼쪽 **개인업무**에서 준비된 세부업무 하나를 열어봅니다.
4. 사용법이 궁금하면 화면 제목 옆 **도움말** 또는 왼쪽 **온이음 사용 안내**를 엽니다. 전체 사용 안내는 로그인 전에도 볼 수 있습니다.

**업무 담당자 1·2는 같은 권한의 서로 다른 시연 계정**입니다. 기본 계정은 각각 송주무관과 조주무관입니다. 오른쪽 위 **역할 전환**으로 같은 부서의 다른 계정을 체험하고, 다른 부서를 보려면 로그아웃 후 첫 화면에서 부서와 계정을 선택합니다.

### 처음 해볼 일

온이음의 업무는 **업무 묶음 → 실행할 과제 → 수행 단계 → 실제 수행 기록**으로 연결됩니다.

| 화면의 용어 | 뜻 | 예시 |
| --- | --- | --- |
| **단위업무** | 관련된 일을 모아 놓은 업무 묶음 | 예산 관리 |
| **세부업무** | 담당자가 실제로 수행하는 과제 | 월별 집행 현황 보고 |
| **절차** | 누가·무엇을·어떻게 수행할지 정한 단계 | 자료 취합 → 검토 → 보고 |
| **회차** | 같은 업무를 한 번 수행하는 일정과 기록 | 11월 보고, 12월 보고 |

처음에는 **개인업무 → 단위업무 추가 → 세부업무 추가**로 한 건을 만들거나, **AI 업무등록**으로 초안을 검토해 등록하세요. 세부업무에서 설명·근거·절차를 저장한 뒤 **일정·수행**에서 날짜와 수행 결과를 기록합니다. 저장한 날짜는 **업무 일정** 달력에서 확인합니다.

**저장은 화면별로 진행합니다.** 업무 기준·절차, 일정, 생산 문서·집행내역, 성과는 각 저장 버튼으로 반영합니다. 성과는 저장 후 **성과 · 평가**에서 별도로 제출하고, 담당자 변경은 **인수인계**에서 승인을 받습니다.

## 시연 순서

### 기본 시연: 업무를 만들고, 수행하고, 다음 담당자에게 넘기기

**송주무관이 업무를 준비하고 → 최과장이 인계를 승인하고 → 조주무관이 이어받는 흐름**입니다. 세 계정 모두 **데이터정보화담당관실**을 선택합니다.

| 순서 | 계정 | 화면에서 할 일 | 확인할 결과 |
| --- | --- | --- | --- |
| **1. 업무 등록** | 업무 담당자 1 · **송주무관** | **개인업무 → AI 업무등록**에 설명이나 파일을 넣고 **AI로 업무 초안 만들기**를 누릅니다. 결과를 확인한 뒤 **검토한 업무 등록**을 누릅니다. 수기로 단위·세부업무를 만들어도 됩니다. | 단위업무 아래에 세부업무가 만들어집니다. |
| **2. 업무 설명 작성** | 송주무관 | 세부업무를 열고 **업무 기준 수정 → 업무 개요**에서 설명과 첨부파일을 연결합니다. 파일로 AI 설명 초안을 만들었다면 검토·적용 후 **변경사항 저장**을 누릅니다. | 업무 목적과 수행 내용이 저장됩니다. |
| **3. 절차도 작성** | 송주무관 | 필요한 **관련 근거**를 저장하고 **절차 → AI로 절차·절차도 작성 → AI 업무 분석·절차 만들기**를 누릅니다. 초안·인용·경고를 검토하고 **원문 자료, 담당자와 진행 순서를 확인했습니다**를 체크한 뒤 **초안 저장·절차도 반영**을 누릅니다. 수기 작성도 가능합니다. | 누가·무엇을·어떻게 하는지 절차도로 확인합니다. |
| **4. 일정·수행 기록** | 송주무관 | **일정·수행 → 일정 등록 → 일정 저장**을 진행합니다. 수행 가능한 첫 절차의 결과를 입력하고 **절차 완료**를 누릅니다. | 달력에 일정이 표시되고 진행률·수행 결과가 남습니다. |
| **5. 인계 요청** | 송주무관 | **인수인계 → 인수인계 요청**에서 새 담당자로 **조주무관**을 선택합니다. 넘길 단위업무·세부업무와 사유를 확인하고 **부서장 승인 요청**을 누릅니다. | 승인 대기 요청이 생깁니다. 승인 전까지 담당자는 송주무관입니다. |
| **6. 부서장 승인** | 역할 전환 → 부서장 · **최과장** | **인수인계 → 승인 대기 → 검토 및 승인**에서 대상 업무와 후임을 확인하고 **승인하여 배정**을 누릅니다. | 승인 후 담당자가 조주무관으로 변경됩니다. |
| **7. 후임자 확인** | 역할 전환 → 업무 담당자 2 · **조주무관** | **개인업무**에서 이어받은 업무를 열고 **일정·수행**, **업무 일정**을 확인합니다. | 업무 설명·절차와 진행 중인 일정·수행 기록을 이어받습니다. 별도 인수 수락은 필요 없습니다. |

시연 전에 다음을 확인하면 흐름을 끝까지 따라가기 쉽습니다.

- **업무분장이 이미 확정됐다면** 부서장 계정의 **부서 업무 관리 → 재작성 허용**을 먼저 진행합니다. 새 업무와 절차를 작성할 수 있게 한 뒤 송주무관으로 돌아옵니다.
- **AI 업무등록에 사용한 파일은 새 업무에 자동 첨부되지 않습니다.** AI 설명 생성을 체험하려면 해당 세부업무의 업무 개요에 파일을 별도로 연결하고 본문을 확인합니다. AI 연결이 준비되지 않았다면 수기로 작성해도 인수인계 흐름을 확인할 수 있습니다.
- **진행 중인 업무를 이어받는 모습을 보려면 일부 절차를 미완료로 남기세요.** 검토 절차는 지정 검토자 또는 부서장이 처리합니다. 인계할 단위업무에는 실제 세부업무와 일정이 있어야 비교할 기록이 생깁니다.

기존 요청과 수행 기록은 자동 초기화되지 않습니다. 다시 시연할 때는 새 예시 업무를 만들거나 현재 처리 상태를 확인하세요. 자세한 안내는 [담당자 1·2 시연](docs/USER-GUIDE.md#업무-담당자-12-시연)을 참고하세요.

### 이어서 확인할 기능

| 시연 주제 | 확인 순서 |
| --- | --- |
| **반기 성과 제출·평가** | 현재 담당자가 세부업무의 **성과** 탭에서 500자 이내로 결과를 저장 → **성과 · 평가 → 업무 비중 설정**에서 각 단위업무 최소 1점·합계 50점으로 저장 → **제출하기** → 부서장이 제출된 성과에 점수·의견을 입력해 평가 확정 |
| **여러 부서에 공통업무 배포** | 작성자가 **공통 세부업무 작성** → 작성 부서장 승인 → 대상 부서 담당자의 팀 배정 → 팀장의 개인 배정 → 담당자의 **내 업무에 등록** → 작성자가 부서별 진행 현황 확인 |
| **업무분장표와 예산 조회** | **업무분장표**에서 담당 관계·절차도를 조회하고 Excel·PDF 다운로드 → **부서장·부서 담당자·관리자 계정으로 전환** → **부서 예산 집계**에서 조회 가능한 부서의 연결 예산과 집행 현황 확인 |

성과는 인수인계나 절차 완료만으로 자동 제출되지 않습니다. 비중이 있는 단위업무마다 성과를 작성해야 합니다. 다른 부서까지 연결하는 상세 시연은 [통계연보 공통업무 시연](docs/DEMO-STATISTICS-YEARBOOK.md)에 있습니다.

## 기능과 메뉴 한눈에 보기

왼쪽 메뉴는 **내 업무 / 협업 / 부서 관리 / 조직·시스템**으로 묶여 있습니다. 접힌 그룹을 펼치면 관련 메뉴가 보이고, 역할에 따라 사용할 수 있는 메뉴가 달라집니다.

| 하고 싶은 일 | 메뉴 · 현재 제공 기능 |
| --- | --- |
| 내 업무 정리 | **개인업무** — 단위·세부업무 추가·수정·이동·삭제·복원, 중요도, 협업·지원 담당자, AI 업무등록 |
| 업무 자료와 수행 관리 | **세부업무 상세** — 업무 개요, 관련 근거, 절차, 일정·수행, 성과, 예산·집행. 지시사항에는 월별 실적 추가 |
| 파일·법령으로 업무 작성 | 개요 파일의 본문 추출·AI 설명 초안, 법령·행정규칙 검색과 조문 가져오기, 근거를 참고한 AI 절차·절차도 |
| 일정 확인·반복 수행 | **업무 일정 / 일정·수행** — 절차별 날짜, 현재 회차 진행, 지난 회차, 수행 결과 정정과 이력 |
| 여러 부서에 업무 요청 | **공통업무 · 지시사항** — 작성 부서장 배포 승인, 대상 부서별 배정·진행 현황, 지시사항 월별 실적 |
| 팀과 담당자에게 배정 | **배정·승인 관리 / 공통업무** — 부서 담당자의 팀 배정, 팀장의 개인 배정, 담당자의 내 업무 등록 |
| 담당자를 바꾸거나 부재에 대비 | **인수인계 / 업무대행** — 직접 인계, 긴급 부서 보관·재배정, 남은 역할 정리, 기간제 대행 요청·승인 |
| 부서 업무 검토 | **부서 업무 관리** — 팀·직원별 업무 검토, 업무분장 확정, 사유를 남기는 재작성 허용 |
| 업무와 담당 관계 공유 | **업무분장표** — 부서·팀·이름 검색, 절차도 조회, Excel·PDF 다운로드, 기본·현재 대행자 표시 |
| 예산과 집행 확인 | **예산·집행 / 부서 예산 집계** — 확정 예산 검색·연결, 집행내역·잔액, 부서별 예산 집계. 관리자 예산 원장 관리 |
| 반기 성과 평가 | **성과 · 평가** — 500자 이내 성과와 참고 파일, 중요도 기반 비중 제안, 합계 50점 제출·회수·평가 |
| 사람과 시스템 관리 | **조직 · 구성원 / 관리자** — 조직·인사정보·기본 대행자, AI 모델 설정, AI·DB·파일 연결 시험, 구현 현황·버전·감사 기록 |
| 업무 찾기·처리 알림 | 상단 검색과 알림 — 접근 가능한 업무 검색, 승인·평가 등의 관련 화면으로 이동 |

## 역할과 승인 흐름

| 역할 | 주로 맡는 일 |
| --- | --- |
| 업무 담당자 | 본인 업무 작성·수행·성과 제출, 공통업무 배포 요청, 업무대행·인수인계 요청 |
| 팀장 | 팀으로 배정된 공통업무의 담당자 지정, 본인 업무와 지정 검토 수행 |
| 부서 담당자 | 받은 공통업무의 팀 배정, 부서 보관·재배정 지원, 성과 제출 현황과 부서 예산 조회 |
| 부서장 | 공통업무 배포·업무대행·인수인계 승인, 부서 업무분장 확정, 반기 성과 평가 |
| 관리자 | 조직·구성원·예산 원장·연결 설정 관리, 업무 관리 지원과 감사 기록 확인 |

**공통업무 전용 추가 권한은 없습니다.** 일반 업무 담당자도 공통 세부업무를 작성할 수 있습니다. 배포 흐름은 **작성 → 작성 부서장 승인 → 대상 부서 접수 → 부서 담당자의 팀 배정 → 팀장의 담당자 배정 → 담당자의 개인업무 등록**입니다. 대상 부서를 추가할 때도 승인을 받습니다. 관리자는 부서장 전용 승인을 대신하지 않습니다.

업무분장표에서는 다른 부서의 업무명·담당 관계·절차도를 조회할 수 있습니다. 이 조회가 다른 부서의 업무 설명·첨부파일·예산·성과 상세에 대한 접근 권한을 넓히지는 않습니다.

## 처음 사용할 때 알아두면 좋은 점

- **저장은 화면별로 합니다.** 업무 기준, 절차, 일정, 수행 기록, 성과는 각 화면의 저장 버튼으로 반영합니다. 파일도 업로드한 뒤 연결할 업무나 성과를 저장해야 합니다.
- **업무분장 확정 후에도 수행은 계속합니다.** 기준·담당 관계를 바꾸려면 부서장의 **재작성 허용**이 필요하지만 일정·수행 기록·성과는 계속 입력할 수 있습니다.
- **성과 저장과 제출은 다릅니다.** 단위업무별 비중은 각각 최소 1점인 정수, 합계 50점입니다. 비중이 있는 단위업무마다 성과가 필요하며, 제출 후 수정은 평가 전 **제출 회수**로 진행합니다.
- **기본 대행자와 실제 업무대행은 다릅니다.** 기본 대행자는 연락·협조를 위한 지정 정보입니다. 기간제 대행은 별도 요청과 부서장 승인 후 해당 기간에만 적용됩니다. 인수인계는 담당자를 변경합니다.
- **AI 초안은 확인 후 적용합니다.** 실행 시 입력 내용과 선택 문서 본문이 BizRouter로 전송됩니다. 스캔 문서 자동 OCR은 제공하지 않으며, 취소·시간 초과 후 입력을 보관하려면 창을 닫기 전에 복사하세요.

자세한 사용 순서와 막히는 단계의 해결 방법은 [사용 안내](docs/USER-GUIDE.md)에서 확인하세요. 앱의 **온이음 사용 안내 → 자주 묻는 질문**에서는 단어 검색과 주제별 필터를 사용할 수 있습니다. 숨긴 화면 안내는 제목 옆 **도움말**로 다시 열 수 있습니다.

## 시연 데이터

초기 가상 조직은 **3개 부서, 9개 팀, 33개 계정**입니다. 각 팀에 팀장 1명·팀원 2명이 있고, 부서장 3명과 시스템 관리자 3명을 포함합니다. 관리자 수정과 시연 진행에 따라 현재 데이터는 달라질 수 있습니다. 이름·연락처·업무는 가상이며 이메일은 `ieum.example` 도메인을 사용합니다.

| 부서 | 팀 | 부서장 |
| --- | --- | --- |
| 기획재정담당관실 | 기획팀 · 예산팀 · 국회팀 | 한과장 |
| 혁신행정담당관실 | 혁신팀 · 청년팀 · 행정지원팀(가칭) | 유과장 |
| 데이터정보화담당관실 | 정보기획팀 · 데이터팀 · 정보자원팀 | 최과장 |

**조직 · 구성원**에서 소속 부서의 팀·직원·연락처를 확인하며, 관리자는 전체 부서를 관리합니다. 기본 예산업무와 통계연보 예시는 기존 기록을 지우지 않고 보충합니다. 시연을 다시 진행해도 이미 처리한 승인이나 수행 기록을 자동으로 초기화하지 않습니다.

## 설치와 연결

일반 로컬 실행에는 외부 연결이 필수는 아닙니다. 필요한 기능의 설정만 프로젝트 `.env.local`에 추가합니다. 실제 비밀값은 Git에 넣지 않고 [.env.example](.env.example)의 빈 항목을 참고하세요.

| 연결 | 설정·확인 위치 | 상세 안내 |
| --- | --- | --- |
| Vercel 가상 계정 로그인 | `IEUM_PROTOTYPE_MODE=true`, 32자 이상 `IEUM_SESSION_SECRET`, 숫자 8자리 `IEUM_PROTOTYPE_ACCESS_CODE` | [Neon·Vercel 설정](docs/PROTOTYPE-NEON-SETUP.md) |
| Neon DB | `DATABASE_URL`, `IEUM_WORKSPACE_ID` | [설정·데이터 이관](docs/PROTOTYPE-NEON-SETUP.md) |
| Neon Object Storage | `IEUM_STORAGE_PROVIDER=neon`, `AWS_*`, 버킷·CORS | [파일 저장소 설정](docs/PROTOTYPE-NEON-SETUP.md) |
| BizRouter AI | `BIZROUTER_API_KEY`, 관리자 저장 모델 또는 `BIZROUTER_MODEL` | [관리자 연결·모델 설정](docs/ADMIN-INTEGRATIONS.md) |
| 국가법령정보센터 | `LAW_API_OC` | [법령 API 설정](docs/LAW-API-SETUP.md) |

Vercel 설정은 로컬로 자동 전달되지 않습니다. 환경변수를 변경하면 로컬 서버를 재시작하거나 Vercel에서 재배포합니다. **관리자 → 연결·테스트**에서 설정 여부와 실제 연결 결과를 확인할 수 있습니다. AI 모델은 허용된 `json_schema` 지원 모델 중 선택하며, 관리자 저장값이 서버 기본값보다 우선합니다. 관리자에서 모델만 바꾸면 다음 요청부터 적용되어 재배포가 필요하지 않습니다.

### 기존 데이터 이관과 파일 저장

같은 `DATABASE_URL`과 `IEUM_WORKSPACE_ID`를 `.env.local`에 설정한 뒤 순서대로 실행합니다.

```powershell
npm run neon:check
npm run neon:import
# 비교 결과와 대상 워크스페이스를 확인한 뒤 적용
npm run neon:import:apply
```

이관은 `.data/workspace.json`을 사용하며 로컬 원본을 보존합니다. `.qa`·`.qa-data`는 합치지 않습니다. DB 내용이 다르면 중단하고, 명시적 `--replace`를 사용할 때도 먼저 DB 내용을 로컬 백업합니다. `scripts/setup-neon.ts`는 새 가상 데이터 설치용이므로 기존 업무를 옮길 때는 `neon:import`를 사용합니다.

Neon 파일 저장은 비공개 버킷을 사용합니다. `npm run neon:storage:setup -- --origin https://실제-프로젝트.vercel.app`으로 앱 주소에 맞는 CORS를 설정합니다. 파일당 10MB 이하를 서명된 주소로 직접 업로드하고 크기·해시 확인 후 첨부 목록에 등록합니다. 기존 로컬 첨부는 보존하며, 저장소 연결만 바꾼다고 기존 파일이 자동 이관되는 것은 아닙니다.

### AI·문서 처리 범위

HWP·HWPX·PDF·DOCX·XLSX·XLS·PPTX는 Kordoc, TXT·CSV는 텍스트로 읽습니다. 파일만 보관할 수 있지만 AI 분석에는 읽을 수 있는 본문이 필요합니다. 문서는 150쪽 또는 섹션, 추출 본문은 20만 자 이하입니다. 절차 분석은 개요 파일 최대 10개·관련 근거 최대 20개·합계 60,000자, 절차·성과 참고 파일은 각각 최대 30개입니다. AI 업무등록은 단위업무 최대 5개·세부업무 전체 30개를 검토 후 등록합니다.

AI 업무등록·업무 설명·절차 생성은 서버 처리 180초, 브라우저 대기 190초, API `maxDuration` 200초를 사용합니다. 배포 플랫폼도 200초 이상 실행을 허용해야 하며 이 코드가 플랫폼 상한을 늘리지는 않습니다. 중복 실행과 취소된 결과 반영을 차단하고 오류 후 유료 분석을 자동 재전송하지 않습니다. `npm run bizrouter:check`는 관리자 저장 모델이 아닌 환경변수 모델을 가상 자료로 시험합니다.

법령·행정규칙 검색으로 가져온 조문은 가져온 시점의 본문으로 보관되며 개정 시 자동 갱신되지 않습니다. 흐름도의 역할·근거 구성은 [korea100 데이터 계약](https://github.com/hosungseo/korea100/blob/main/docs/data-contract.md)을 참고했습니다.

## 개발과 검증

```powershell
npm run typecheck
npm test
npm run build
npm start
```

코드를 수정한 뒤에는 `npm run dev`로 확인하거나 새로 빌드합니다. **Start-Ieum.cmd**는 기존 빌드가 있으면 그것을 실행하므로 소스 수정만으로 기존 빌드가 갱신되지는 않습니다.

HTTP 검증은 먼저 빌드한 후 격리된 QA 서버에서 실행합니다.

```powershell
npm run qa:serve
# 다른 터미널
node tests/http-workflow.mjs http://127.0.0.1:3001
```

`qa:serve`는 `.env.local`에 원격 연결값이 있어도 `IEUM_STORE=local`과 로컬 파일 저장을 강제하고 `.qa-data`를 사용합니다. 시작 로그의 `로컬 QA` 및 첫 조회 후 `저장소: 로컬 파일`을 확인하세요. `IEUM_QA_DATA_DIR`, `IEUM_QA_PORT`로 경로·포트를 바꿀 수 있으며 설정은 자식 프로세스에만 적용됩니다. PowerShell과 Git Bash에서 같은 명령을 사용합니다.

`IEUM_DATA_DIR`만 바꿔서는 DB가 격리되지 않습니다. `DATABASE_URL`과 함께 설정하면서 `IEUM_STORE`를 생략하면 접근을 거부합니다. 일반 DB 사용은 `IEUM_DATA_DIR`을 비우고, 명시적 DB 사용은 `IEUM_STORE=neon`을 사용합니다. Vercel에서는 로컬 저장을 허용하지 않습니다.

## 현재 범위와 후속 검토

인수인계·업무대행·파일 첨부·법령 조회·앱 내 알림은 현재 화면에서 사용할 수 있습니다. 실제 기관 계정·인증과 사용자 초대, 운영 백업·복구 검증, 기관 행정 시스템 및 외부 알림 채널 연동은 후속 검토 항목입니다. 프로토타입 설정은 [Neon·Vercel 안내](docs/PROTOTYPE-NEON-SETUP.md)를 사용하고, 향후 운영 검토는 [운영 전환 기록](docs/PRODUCTION-READINESS.md)을 참고하세요.

관리자의 **버전 기록**은 릴리스 이력 관리 기능이며 코드를 배포하거나 되돌리지는 않습니다. 화면의 실행 버전은 `package.json` 값을 사용하고 저장된 과거 릴리스 기록과 구분합니다.
