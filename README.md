# 온이음 워크스페이스 · v0.7.0

공공업무의 계획·배정·실행·반기 성과평가를 연결하는 프로토타입입니다. 로컬 또는 Vercel에서 역할별 가상 계정으로 시연하며, Neon DB와 Neon Object Storage를 연결할 수 있습니다.

## 시작

프로젝트 홈은 **D:\Workflow-Project**입니다. 이 폴더의 **Start-Ieum.cmd**를 실행하고 [온이음 열기](http://127.0.0.1:3000)로 접속합니다.

```powershell
cd D:\Workflow-Project
npm run dev
```

Node.js와 현재 설치된 의존성으로 실행합니다. 실행 파일은 완성된 프로덕션 빌드가 있으면 그 빌드를 실행하고, 빌드가 없으면 개발 서버를 실행합니다. 의존성이 없는 새 환경에서는 먼저 `npm ci`를 실행합니다. 프로덕션 빌드는 `npm run build`, 빌드한 앱 실행은 `npm start`입니다.

첫 화면에서 역할과 가상 계정을 고르면 비밀번호 없이 로그인합니다. 일반 역할은 데이터정보화담당관실 계정을 기본으로 선택하며 다른 부서로 바꿀 수 있습니다. 공통업무 담당 역할은 기획재정담당관실 예산담당 주무관 계정으로 시연합니다. 화면 오른쪽 위 **역할 전환**에서 같은 부서의 다른 역할을 확인합니다. 다른 부서의 시연은 로그아웃 후 첫 화면에서 선택합니다. **로그아웃**하면 소개·로그인 화면으로 돌아갑니다. 세션 없이 업무 조회·수정 API에 접근할 수 없습니다.

초기화면 상단의 **온이음 사용 안내** 또는 아래의 역할별 안내 카드에서 로그인 없이 사용법을 확인할 수 있습니다. 로그인 후 왼쪽 메뉴에서도 같은 안내를 열 수 있으며 현재 역할이 먼저 선택됩니다. 안내에는 처음 시작하기, 6개 권한별 책임·메뉴·처리 순서, 세부업무 탭별 작성 방법, 자주 묻는 질문이 포함됩니다.

## 시연 계정

모든 이름·연락처·업무 정보는 가상 데이터입니다. **조직 · 구성원**에서 자기 부서의 ID, 팀, 권한, 이메일, 전화번호를 확인합니다. 관리자만 세 부서의 전체 구성원과 권한을 볼 수 있습니다. 이메일은 `ieum.example` 도메인입니다.

각 부서는 3개 팀, 각 팀은 **팀장 1명과 팀원 2명**으로 구성합니다. 팀 소속 직원은 총 27명이며, 부서장 3명과 시스템 관리자 3명을 포함해 총 33개 가상 계정입니다. 혁신행정담당관실의 세 번째 팀은 가칭 **행정지원팀**으로 구성했습니다.

| 부서 | 팀 | 팀장 | 팀원 |
| --- | --- | --- | --- |
| 기획재정담당관실 | 기획팀 | 이팀장 | 김담당, 정주무관 |
| 기획재정담당관실 | 예산팀 | 최팀장 | 박주무관, 한주무관 |
| 기획재정담당관실 | 국회팀 | 윤팀장 | 서주무관, 장주무관 |
| 혁신행정담당관실 | 혁신팀 | 박팀장 | 강담당, 임주무관 |
| 혁신행정담당관실 | 청년팀 | 정팀장 | 류주무관, 안주무관 |
| 혁신행정담당관실 | 행정지원팀(가칭) | 홍팀장 | 유주무관, 전주무관 |
| 데이터정보화담당관실 | 정보기획팀 | 오팀장 | 조주무관, 신주무관 |
| 데이터정보화담당관실 | 데이터팀 | 김팀장 | 오담당, 송주무관 |
| 데이터정보화담당관실 | 정보자원팀 | 배팀장 | 문주무관, 백주무관 |

부서장은 기획재정담당관실 한과장, 혁신행정담당관실 유과장, 데이터정보화담당관실 최과장입니다. 부서장과 시스템 관리자는 **부서 직속**으로 표시하고 팀 수와 팀 정원에서 제외합니다. **조직 · 구성원**에서는 팀별 명단을 확인하고, 로그인과 역할 전환에서는 팀명이 포함된 계정을 선택합니다.

이관리자·나관리자·서관리자는 관리자 계정입니다. 김담당·오담당은 부서 담당자 역할에 공통업무 관리 권한이 추가되어 있습니다. 기획재정담당관실 **박주무관(`u-jiho`)은 예산담당 주무관**으로, 개인 담당자 역할과 공통업무 관리 권한을 함께 갖습니다. 공통업무를 만들고 총괄할 수 있어도 부서 담당자나 팀장의 배정 권한이 생기지는 않습니다.

박주무관의 개인업무에는 예산 관련 업무 묶음과 실행 과제를, 데이터정보화담당관실 송주무관의 개인업무에는 데이터사업 예산 예시를 제공합니다. 공통 예산업무를 통해 총괄 현황과 부서별 수행 흐름도 확인할 수 있습니다. 이 예시는 기존 업무를 지우지 않고 추가되며, 다시 보충해도 같은 항목을 중복 생성하지 않습니다.

## 한 번에 확인하는 시연 순서

1. **공통업무 담당 → 기획재정담당관실 박주무관**으로 로그인합니다. 공통업무에서 예산업무 예시를 확인하거나 새 업무·지시사항을 만들고, 사업명과 전체/선택 부서를 지정해 배포합니다.
2. **부서 담당자 → 기획재정담당관실 → 김담당** 화면에서 해당 배포의 팀 배정을 누르고 **예산팀 · 최팀장**을 선택합니다.
3. **팀장 → 기획재정담당관실 → 최팀장**으로 전환하고 개인 배정에서 **박주무관**을 지정합니다.
4. **개인 담당자 → 기획재정담당관실 → 박주무관**으로 전환합니다. 개인업무에서 단위업무를 만들고 수신한 공통업무를 **내 업무에 등록**합니다.
5. 등록된 세부업무를 열어 업무 설명, 예산, 집행 내역과 법령·지침·국정과제·지시사항 근거를 추가합니다.
6. **일정·수행 → 일정 등록**에서 저장된 절차별 시작일·종료일을 정합니다. 전체 기간은 절차 날짜에 맞춰 자동으로 정해지며, 날짜가 없는 절차는 일정 미정으로 둡니다. 저장한 일정은 **업무 일정** 달력에서 확인합니다. 선행 절차부터 완료를 표시하며, 검토 절차는 검토자 또는 부서장 계정에서 처리합니다.
7. 세부업무의 **성과** 탭에서 연도·반기를 선택하고 성과 내용을 **500자 이내**로 작성합니다. 필요한 참고 파일을 첨부하고 **성과 저장**을 누릅니다. 제목·근거 설명·지표는 별도로 입력하지 않습니다. **성과 · 평가**에서 단위업무별로 모인 성과를 확인하고 업무 비중을 합계 **50점**으로 설정한 뒤 **제출하기**를 누릅니다. 비중이 있는 단위업무마다 성과가 필요하며 평가 대상이 아닌 업무는 0점으로 설정할 수 있습니다.
8. **부서장**으로 전환하여 제출된 직원별 성과를 확인합니다. 단위업무에 모인 성과 내용과 참고 파일을 검토하고 각 업무 비중 이내에서 점수와 의견을 입력해 평가를 확정합니다. 제출 후에는 성과·비중이 잠기며 평가 전 **제출 회수**로 수정할 수 있습니다. **부서 담당자**는 성과 · 평가의 **부서 성과 제출 현황**에서 직원별 제출 여부와 일시를 조회합니다.
9. 공통업무를 만든 계정에서 대상 부서별 현재 배정 단계, 담당 팀·담당자, 진행 현황과 다음 조치를 함께 확인합니다.
10. **관리자 → 기획재정담당관실 → 이관리자**에서 구현 현황·다음 개발 항목·버전 기록·감사 이력을 확인합니다.

지시사항은 배포 시 대상 부서에 세부업무가 자동 생성됩니다. 이후 팀·개인 배정과 단위업무 등록에서 같은 업무를 이어받아 중복 생성하지 않습니다.

## 지시사항과 월별 실적 관리

**공통업무 만들기 → 지시사항**에서 지시자(장관·차관·실장·국장)와 지시일자를 입력합니다. 지시일자는 오늘까지의 날짜만 선택할 수 있습니다. 기존 지시사항의 누락된 정보는 관리 권한이 있는 계정에서 **지시정보 수정**으로 보완합니다.

배정된 업무를 내 단위업무에 등록한 담당자는 세부업무의 **월별 실적** 탭 또는 공통업무의 **월별 실적 입력**에서 실적, 다음 달 계획, 특이사항을 저장합니다. 지시일자가 속한 달부터 이번 달까지 관리하며 같은 달은 기존 기록을 수정합니다. 업무 반복 주기와 별개로 매월 기록할 수 있고 업무분장 확정 후에도 입력할 수 있습니다. 업무가 완료되면 지난 기록은 조회할 수 있지만 수정할 수 없습니다.

**기획재정담당관실 기획팀**은 공통업무의 **장·차관 지시사항**에서 다른 등록자가 만든 업무도 함께 관리합니다. 지시정보와 배포 대상을 관리하고 월·지시자·실적 입력 여부로 부서별 현황을 조회할 수 있습니다. 월별 실적 작성은 해당 업무의 현재 담당자만 할 수 있으며, 기획팀의 통합 관리 권한은 다른 부서의 일반 세부업무 내용이나 반기 성과에 대한 추가 열람 권한을 부여하지 않습니다. 시연에서는 **팀장 → 기획재정담당관실 → 이팀장**으로 확인합니다.

## 공통업무 배정과 총괄

공통업무는 **부서 접수 → 팀 배정 → 개인 배정 → 내 업무 등록 → 수행·완료** 순서로 이어집니다. 담당자를 지정한 상태와 개인이 실제 단위업무에 등록한 상태를 구분해 보여줍니다.

| 역할 | 현재 단계에서 할 일 |
| --- | --- |
| 공통업무 담당자 | 공통업무·지시사항을 만들고 대상 부서 지정. 자신이 만든 업무의 부서별 배정·진행 요약 확인 |
| 부서 담당자 | 자신의 부서에 도착한 업무를 담당 팀과 팀장에게 배정 |
| 팀장 | 자신에게 배정된 업무를 개인 담당자에게 배정 |
| 개인 담당자 | 배정받은 업무를 본인 단위업무에 등록하고 절차 수행·진행 상황 기록 |

총괄 화면에서는 대상 부서별 담당 팀·담당자와 현재 단계, 진행 현황을 함께 확인합니다. 다른 부서의 배정·진행 요약을 볼 수 있어도 세부업무의 설명, 예산·집행, 성과·첨부 내용에 대한 열람·수정 권한은 확대되지 않습니다. 세부업무는 기존 접근 권한이 있는 경우에만 열 수 있습니다.

진행률은 최신 수행 회차의 전체 절차 중 완료한 절차 비율입니다. 회차가 없거나 이전 회차 완료 후 새 계획이 생겼다면 현재 업무 절차를 기준으로 합니다. 개인 등록 전에는 0%로 표시하며, 평균 진행률은 현재 조회할 수 있는 대상 부서들의 진행률을 동일한 비중으로 평균한 값입니다.

배정 단계와 수행 상태를 구분하므로 일시중지·보관·삭제 상태도 따로 확인할 수 있습니다. 기한 경과는 한국 날짜를 기준으로 마감일이 지났고 아직 완료하지 않은 항목이며, 일시중지·보관·삭제된 항목은 기한 경과 집계에서 제외합니다.

## 개인업무 구조와 관리

**단위업무는 관련된 일을 모으는 업무 묶음**, **세부업무는 실제로 수행하는 실행 과제**입니다. 예를 들어 '예산 관리' 단위업무 아래에 '분기 집행 현황 보고', '계약 이행 점검' 세부업무를 등록합니다. 개인업무 화면은 이 관계를 단위업무별로 묶어서 보여줍니다.

| 구분 | 관리 범위 |
| --- | --- |
| 본인 단위업무 | 추가, 이름·설명 수정, 삭제, 휴지통에서 복원 |
| 직접 만든 세부업무 | 추가, 내용 수정, 소속 단위업무 이동, 삭제, 휴지통에서 복원 |
| 배정받은 공통업무 | 자신의 단위업무에 등록하고 소속 단위업무 변경. 배정된 공통업무의 삭제는 제한 |

활성 세부업무가 있는 단위업무를 삭제하려면 세부업무를 다른 단위업무로 옮기거나 먼저 삭제해야 합니다. 삭제한 단위업무와 세부업무는 개인업무의 휴지통에서 확인하고 복원합니다.

개인 세부업무의 삭제·복원은 해당 업무의 담당자 또는 관리자만 할 수 있고, 진행 중인 인수인계에 연결된 업무는 삭제할 수 없습니다. 삭제해도 기존 기록은 보존되며, 복원하기 전까지 수정·절차 진행·성과 입력은 제한됩니다. 원래 단위업무도 삭제했다면 단위업무를 먼저 복원하거나 다른 활성 단위업무를 선택해 세부업무를 복원합니다.

- 연도별 상반기/하반기 성과(500자 이내)와 참고 파일, 중복 제출 방지, 부서장 평가·보완

## 프로토타입 Neon 연결과 기존 데이터 이관

**[Neon·Vercel 프로토타입 설정 안내](docs/PROTOTYPE-NEON-SETUP.md)**에서 각 설정값을 어디에서 복사하고 어디에 저장하는지 확인할 수 있습니다. 현재 프로젝트에는 기관용 인증이나 운영 전환 작업이 필요하지 않습니다. Vercel에서도 `IEUM_PROTOTYPE_MODE=true`와 `IEUM_SESSION_SECRET`을 설정하면 기존 역할 선택 로그인을 사용합니다.

Vercel에 연결한 DB 값은 로컬로 자동 전달되지 않습니다. 이관 명령을 실행하려면 같은 `DATABASE_URL`과 `IEUM_WORKSPACE_ID`를 `.env.local`에 설정합니다. `npm run neon:check`로 연결 상태를 확인하고, `npm run neon:import`로 현재 `.data/workspace.json`과 DB를 비교한 뒤 `npm run neon:import:apply`로 이관합니다. 로컬 원본은 보존되며 `.qa`·`.qa-data`의 자동화 테스트 데이터는 합치지 않습니다. 기존 DB 내용이 다르면 명령이 중단되며, 명시적 `--replace`를 사용할 때에도 먼저 기존 DB 내용을 로컬 백업합니다.

파일은 `IEUM_STORAGE_PROVIDER=neon`과 Neon Storage 연결값을 설정하면 비공개 버킷에 보관합니다. `npm run neon:storage:setup -- --origin https://실제-프로젝트.vercel.app`으로 브라우저 업로드에 필요한 CORS를 설정합니다. 10MB 이하 파일은 서명된 주소로 Neon에 직접 업로드하고 크기·해시 확인 후 첨부 목록에 등록합니다.

## 향후 운영 검토 참고

이전에 작성한 **[운영 전환 검토 기록](docs/PRODUCTION-READINESS.md)**은 향후 참고 자료입니다. 현재 프로토타입 설정에는 위의 Neon·Vercel 안내를 사용합니다. `scripts/setup-neon.ts`는 새로운 가상 데이터를 설치하는 스크립트이므로, 현재 테스트 데이터를 그대로 옮길 때는 `neon:import` 명령을 사용합니다.

실제 기관 계정·인증과 사용자 초대, 운영 DB·파일 저장소·백업 복구 검증, 공식 법령·행정 시스템 연동, 알림 채널 연동은 후속 항목입니다. 기존 인수인계·자료 관리 소스와 API는 보존했으나 새 화면의 주 메뉴에는 아직 통합하지 않았습니다. 정확한 범위는 관리자 화면에서 확인할 수 있습니다.

Git 저장소에는 현재 앱의 소스·설정 예시·테스트·문서를 포함합니다. `.env.local` 등 비밀 설정, `.data`의 시연 데이터와 첨부파일, `.qa`·`.qa-data`의 검증 데이터, `etc`의 이전 앱·원본 자료, 빌드 결과와 의존성은 제외합니다. 실제 비밀값은 배포 서비스의 환경변수 관리 기능에 등록하고 `.env.example`에는 입력하지 않습니다.

## 검증

```powershell
npm run typecheck
npm test
npm run build
```

HTTP 흐름 검증은 **로컬 저장을 강제하는 테스트 서버**에서 실행합니다. `.env.local`에 DB·파일 저장소 연결값이 있어도 `qa:serve`는 `IEUM_STORE=local`과 로컬 파일 저장을 적용하고, `.qa-data`에 가상 데이터를 저장합니다.

```powershell
npm run qa:serve
# 다른 터미널
node tests/http-workflow.mjs http://127.0.0.1:3001
```

PowerShell과 Git Bash에서 같은 명령을 사용합니다. 먼저 `npm run build`를 실행하고, 시작 로그의 `로컬 QA` 및 첫 조회 후 `저장소: 로컬 파일`을 확인해 주세요. 경로나 포트를 바꾸려면 `IEUM_QA_DATA_DIR`, `IEUM_QA_PORT`를 지정할 수 있습니다. 테스트 서버를 종료하면 별도로 설정한 저장 모드는 부모 터미널에 남지 않습니다.

`IEUM_DATA_DIR`만 바꿔서는 DB 연결이 격리되지 않습니다. `DATABASE_URL`과 함께 설정하면서 `IEUM_STORE`를 생략하면 저장소 접근을 거부합니다. 일반 DB 사용은 `IEUM_DATA_DIR`을 지우고, 명시적 DB 사용은 `IEUM_STORE=neon`을 설정하세요. Vercel은 로컬 저장을 허용하지 않습니다.

## 부서 업무분장과 세부업무 절차

부서장은 업무 홈에서 부서원별 단위·세부업무와 진행 상황을 요약해 보고, **부서 업무분장**에서 전체를 검토합니다. **업무분장 확정**은 작성 중인 업무의 기준을 함께 확정하고 부서의 정의·배정을 잠급니다. 직원은 수행 체크, 메모, 성과 기록을 계속할 수 있습니다. 변경이 필요하면 부서장이 **재작성 허용**에서 사유를 남기고, 직원이 수정한 후 다시 확정합니다. 확정본은 차수별로 보존됩니다. 기존 저장소는 미확정 상태로 시작하며 자동 확정하지 않습니다.

세부업무 탭은 **업무 개요 → 절차 → 일정·수행 → 성과 → 관련 근거 → 예산·집행** 순서입니다. 지시사항 업무에는 마지막에 **월별 실적**이 추가됩니다. 절차는 **누가·무엇을·어떻게**를 중심으로 작성하고 필요한 자료를 각 절차에 파일 단위로 첨부합니다. 절차별 참고 파일과 성과 참고 파일은 각각 최대 30개, 파일당 10MB까지 연결할 수 있습니다. 파일 업로드 후 해당 변경사항 또는 성과를 저장해야 연결이 완료됩니다.

**수기로 절차 추가**로 새 단계를 만들고 **위로·아래로** 버튼으로 표시 순서를 조정합니다. 표시 순서를 바꿔도 선행 관계와 날짜는 유지됩니다. 각 단계의 **선행 절차**를 선택하고, 동시에 진행할 단계끼리는 선행 관계를 연결하지 않습니다. 병렬 절차는 겹치는 일정으로 등록할 수 있습니다. **수정사항 저장·절차도 반영**으로 저장하고 **전체 절차도 보기**에서 확인합니다. 개인업무는 **필수 검토 단계 유지**를 해제한 뒤 불필요한 검토 단계를 삭제할 수 있으며, 공통 필수 단계와 완료한 단계의 기록은 보존합니다.

업무 개요에서 같은 부서의 **협업·지원 담당자**와 **협조 대상 부서**를 지정합니다. **모든 부서 협조**도 선택할 수 있습니다. 부서 협조 결과는 업무 담당자가 취합해 기록하며, 협조 부서 지정은 다른 부서에 업무 열람 권한을 부여하지 않습니다.

현재 회차의 완료 결과는 **수행 결과 정정**에서 사유와 함께 수정할 수 있습니다. 원래 결과·완료 시각·정정자·사유를 이력에 남기고, 이미 완료된 관련 검토는 다시 요청합니다. 새 회차가 시작된 뒤에는 이전 회차 정정을 차단하며 정정 이력은 지난 회차에서도 확인할 수 있습니다.

업무 개요와 첨부파일을 저장한 뒤 **절차 → AI로 초안 만들기**를 선택할 수도 있습니다. 분석할 개요 파일과 관련 근거를 선택하며 **모든 파일 제외**로 저장한 텍스트만 분석할 수 있습니다. 동일 파일 본문은 중복 전송하지 않으며 분석은 파일 추출부터 최대 90초입니다. 초안의 담당자·수행 내용·선행 관계와 인용을 검토한 뒤 **초안 저장·절차도 반영**을 누르면 현재 절차를 교체·저장합니다. 이후 직접 편집한 내용은 **수정사항 저장·절차도 반영**을 누릅니다. **저장하고 일정 등록**은 편집한 절차를 저장한 뒤 일정·수행으로 이동합니다.

**관련 근거**에서는 법령·지침·국정과제·지시사항과 생산 문서를 관리합니다. HWP·HWPX·PDF·DOCX·XLSX·XLS·PPTX는 Kordoc으로, TXT·CSV는 텍스트로 읽으며 파일과 추출 본문을 확인합니다. 파일만 보관할 수도 있지만 AI 분석에는 읽을 수 있는 본문이 필요합니다. 스캔 문서 자동 OCR과 법령 최신성 확인은 제공하지 않습니다.

BizRouter 연결에는 서버의 `BIZROUTER_API_KEY`와 `BIZROUTER_MODEL` 설정이 필요합니다. `GET /v1/models`에서 `json_schema`를 지원하는 허용 모델 ID를 선택하세요. API 키는 클라이언트로 전달하지 않습니다. AI 분석을 실행할 때 업무 개요·개요 첨부파일에서 읽은 본문·선택한 관련 근거 본문을 BizRouter로 전송합니다. 개요 파일은 최대 10개, 관련 근거는 최대 20개, 전체 본문은 합계 60,000자이며 오류 안내가 적용됩니다. [BizRouter 모델 목록](https://bizrouter.ai/docs/models), [구조화 응답](https://bizrouter.ai/docs/chat-completions).

흐름도의 역할 레인과 근거 표시는 [korea100 데이터 계약](https://github.com/hosungseo/korea100/blob/main/docs/data-contract.md)을 참고했습니다. 생성된 그림은 검토할 업무 절차 초안이며 실제 수행 완료 상태와 구분합니다.

## 개인별 단위업무 평가 · 50점

부서장의 업무 홈과 부서 업무분장에서는 **팀 → 직원 → 단위업무 → 세부업무**를 펼쳐 확인하고 세부업무 상세를 열 수 있습니다. 팀 및 이름·업무 검색으로 범위를 좁힐 수 있습니다.

성과 · 평가에서는 개인이 반기별로 자신의 활성 단위업무 배점을 합계 50점으로 설정합니다. 부서장은 직원별로 모인 세부업무 성과를 단위업무별로 확인하고, 각 배점 범위 안에서 점수와 의견을 입력합니다. 총점은 단위업무별 평가 점수를 더해 계산합니다. 성과 내용과 첨부한 참고 파일을 함께 확인합니다. 기존 성과의 지표와 근거 설명은 보존되며, 이전 근거는 접힌 항목에서 볼 수 있습니다.

평가를 확정하면 배점과 평가 당시 성과를 함께 보존합니다. 이후 업무 이름이나 성과 자료가 바뀌어도 확정된 평가 근거는 그대로 남습니다. 기존 세부업무별 100점 평가 기록은 보존하되 새 50점 평가 총점에 더하지 않습니다. 평가 배점 설정은 업무분장 확정과 별개이며, 업무분장 잠금 상태에서도 가능합니다.

## 업무 회차와 지난 절차

세부업무 상세의 **일정·수행 → 일정 등록**에서 만들어 저장한 절차별 시작일·종료일을 입력하고 **일정 저장**을 누릅니다. 전체 기간은 가장 이른 날짜부터 가장 늦은 날짜까지 자동으로 정해지며 회차 이름을 별도로 입력하지 않습니다. 날짜가 정해진 절차부터 등록할 수 있고, 장소·준비 사항은 접힌 **진행 방법 · 일정 메모**에 적습니다. 이 일정은 업무 기준을 바꾸지 않으므로 업무분장 확정 후에도 담당자 또는 관리자가 등록·수정할 수 있습니다.

절차별 체크리스트와 수행 결과를 입력하고 지정된 검토자가 검토를 완료하면 업무 사이클이 완료됩니다. 기존 일정 미등록 완료 기록은 **업무 사이클 완료**로 보존합니다. 이후 **새 일정 등록**에서 다음 회차 날짜와 세부 내용을 입력하고 시작하면 새 회차의 진행률은 0%가 됩니다.

**지난 회차**에서 완료된 절차, 당시의 일정, 체크리스트, 완료자·완료 시각과 결과를 다시 확인합니다. 다음 회차를 만들어도 이전 기록은 보존됩니다. 업무분장이 확정된 상태에서도 승인된 절차를 그대로 사용해 다음 회차를 수행할 수 있습니다. 절차 내용 자체의 변경은 기존 업무분장 변경 권한을 따릅니다.

현재 회차의 일정은 업무 일정 화면에 연결됩니다. 완료되지 않은 회차가 있으면 다음 회차를 시작할 수 없으며, 회차를 중복 생성하지 않도록 서버에서 확인합니다.
