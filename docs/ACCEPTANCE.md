# 설계서 v0.2 수용 기준 검토

검토 기준일은 2026년 10월 31일입니다. 이 문서는 현재 소스와 `tests/domain.test.ts`를 바탕으로 실제 구현 범위를 구분합니다. **AT01–AT53 전체 통과 보고서가 아닙니다.** 외부 서비스 실계정, 운영 데이터, 배포·복구·부하 시험은 수행하지 않았습니다.

## 표기와 검증 범위

- **로컬 검증**: 관련 핵심 도메인 동작의 자동 테스트가 있습니다. 외부 인프라·화면·모든 예외를 포괄한다는 뜻은 아닙니다.
- **부분 구현**: 일부 구조나 동작이 있으나 원 설계 시나리오 전체를 충족하거나 검증하지 못했습니다.
- **미구현**: 해당 기능의 실행 경로가 아직 없습니다. 설정 화면이나 자료형만으로 구현 완료로 판단하지 않습니다.
- **실환경 미검증**: 어댑터·환경 구성은 존재하지만 실제 공급자와의 종단 검증은 하지 않았습니다.

재실행 명령은 `npm run typecheck`, `npm test`, `npm run build`입니다. 테스트에 AT 번호가 있어도 아래 표에 명시한 한계가 우선합니다. 예를 들어 잘못된 근거 ID 차단 테스트는 실제 조문의 존재나 법적 적용 가능성을 검증하지 않습니다.

현재 타입 검사·도메인 테스트·webpack 프로덕션 빌드를 통과했으며, 별도 [API 검증 기록](API-SMOKE.md)에 로컬 API 시나리오 결과가 있습니다. 데스크톱과 모바일 레이아웃 및 업무 생성·체크·인수 확인 흐름을 브라우저에서 검토했습니다. 테스트의 세부 개수는 추가 회귀 테스트에 따라 바뀔 수 있으므로 실행 출력이 최종 기준입니다.

## 데이터·운영 한계

로컬 저장은 JSON 파일 잠금과 원자적 교체를 사용합니다. 선택적 Neon 저장은 한 워크스페이스의 JSONB 행을 잠그는 방식이며 정규화된 전체 업무 DB, DB 수준 기관 경계·기간 배정 제약, 확장성·가용성 검증을 대신하지 않습니다. 기준시각도 현재 애플리케이션 서버 시각을 사용합니다.

기관 운영 전에는 실제 인증·허용 사용자, 팀·자료 권한, 확정·개정 정책, 저장 위치·전송 정책, 첨부 검사, 백업·복구·보존, 조직개편·퇴사 시 책임 공백, 실행 인프라와 부하를 검증해야 합니다. 앱의 확정·수락 기록을 법정 전자결재·전자서명으로 간주하지 않습니다.
