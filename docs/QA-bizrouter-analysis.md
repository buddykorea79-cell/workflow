# BizRouter 다중 근거 분석 오류 수정 및 검증

검증일: 2026-11-05

## 원인

기존 코드는 모델 목록(`/v1/models`)과 절차 생성 결과에 동일한 700,000바이트 한도를 적용했습니다. 실제 모델 목록은 HTTP 200으로 **3,413,561바이트, 모델 116개**를 반환했습니다. 따라서 분석 요청 전에 목록을 읽다가 중단되었으며, 이 상황에도 “AI 응답이 너무 큽니다. 근거 범위를 줄여…”라는 메시지가 표시되었습니다. 선택한 근거의 양이나 잘못된 API 키가 원인이 아니었습니다.

설정된 `bizrouter/deepseek-v4.1-flash` 모델은 해당 키로 조회되었으며 `json_schema` 응답을 지원했습니다. API 키 값이나 전체 모델 목록은 문서에 기록하지 않습니다.

## 변경

- 모델 목록은 8MiB, 생성 응답은 1MiB로 구분해 제한합니다. 과도한 응답은 스트림을 취소하고 각각 다른 오류로 안내합니다.
- 선택한 근거의 개수와 ID를 요청 JSON 스키마에 반영합니다.
- AI는 모든 선택 근거의 개별 요약과 종합 요약을 작성한 후 절차를 생성합니다. 화면은 종합 요약 → 근거별 요약·인용 확인 → 절차도·단계 편집 순서입니다.
- 각 근거가 정확히 한 번 요약됐는지, 요약과 단계의 인용이 해당 원문에 있는지 검증합니다. 단계의 역할·필수 검토·선행 관계도 계속 검증합니다.
- 누락·잘린 결과·잘못된 인용 또는 절차 형식은 같은 60초 제한 안에서 한 번 자동 보완합니다. 분석 호출은 최대 2회이며 인증·사용 한도·연결·응답 용량 오류는 재시도하지 않습니다.
- 기존 저장 전 변경 감지, 업무 권한과 업무분장 잠금, 사용자의 초안 검토·적용·저장 절차를 유지합니다.

요약은 AI 초안 검토 화면에서 제공됩니다. 업무에 적용·저장하는 대상은 절차와 단계별 원문 인용이며 기존 관련 근거는 보존됩니다. 입력 제한(최대 20개, 합계 60,000자)은 변경하지 않았습니다.

## 검증 결과

| 구분 | 결과 |
| --- | --- |
| 실제 모델 목록 연결 | HTTP 200, 설정 모델 및 구조화 응답 지원 확인 |
| 실제 생성 API | 가상 법령·지침·생산 문서 3개에서 요약 3건, 종합 요약, 절차 7단계 생성 및 인용 검증 성공 |
| 화면의 실제 API 요청 | 격리 저장소에서 근거 3건의 요약과 절차 6단계·절차도 생성 성공 |
| 초안 적용·저장 | 검토 확인 후 적용·저장, 새로고침 뒤 6단계 보존 확인 |
| AI 회귀 테스트 | 16개 통과: 3.4MB 목록, 한도 초과 스트림 취소, 다중 근거 누락·중복·허위 인용, 자동 보완, 권한 검사 포함 |
| 전체 회귀 테스트 | 264개 전부 통과 |
| 빌드·타입 검사 | `npm run build` 성공, 전체 페이지 생성 완료 |

AI 생성 결과는 호출마다 달라질 수 있습니다. 최초 실제 시험에서 근거 요약 누락을 발견하여 검증을 유지하면서 1회 보완 및 정확한 개수·ID 스키마를 추가했습니다. 실제 Neon 업무 데이터는 변경하지 않았고, 실제 업무 본문·첨부파일을 시험용으로 전송하지 않았습니다.

## 재점검

로컬 `.env.local`에 기존 `BIZROUTER_API_KEY`, `BIZROUTER_MODEL`이 설정된 상태에서 다음 명령을 실행합니다.

```powershell
npm run bizrouter:check
```

가상 근거 3개로 실제 API를 호출하므로 BizRouter 사용량이 발생합니다. 결과에는 모델, 요약 건수, 단계 수, 인용 검증 여부, 소요 시간만 표시하며 키·서명값·업무 데이터는 출력하지 않습니다. DB에 저장하거나 기존 절차를 변경하지 않습니다.

화면에서는 **세부업무 → 업무 기준 수정 → 관련 근거 저장 → 절차 → AI로 절차·절차도 만들기 → AI 근거 요약·절차 만들기**를 실행합니다. 요약과 원문 인용을 확인한 다음 초안을 적용하고 **변경사항 저장**을 누릅니다. 새 환경변수나 키 재발급은 필요하지 않습니다.
