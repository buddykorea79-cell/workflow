# D2 안내 문구 적용 준비 감사

작성: 2026-11-08. M12 전체 643개 테스트·타입 검사·빌드 통과 후 소스를 읽은 기준이다. 이 문서는 읽기 전용 조사 결과이며 제품 소스·설정은 변경하지 않았다. D1 등 선행 작업 이후 줄 번호가 이동할 수 있으므로 아래 CSS selector와 문구를 함께 사용한다.

## 승인과 적용 범위

- 원문 D2는 `현재 문구 → 1문장 제안 → 교육용·상태·경고` 표 승인 후 구현을 요구한다.
- `docs/design/review-proposals-2026-11-07.md:3`에 2026-11-07 전체 적용 승인이 기록되어 있다. 이 보고서 때문에 승인을 다시 요청할 필요는 없다.
- 승인표 14행은 교육용 9개, 상태 4개, 경고 1개다. 교육 설명은 접고 기억하되 상태·경고는 항상 표시한다.
- 원문이 지시한 최종 문구표 경로는 `docs/design/copy-review.md`다. 현재 승인표는 다른 파일에 있으므로 구현 때 승인표를 해당 최종 경로에 옮기거나 승인 근거를 링크한 적용표로 만들면 된다. 이번에 허용받은 문서는 이 파일뿐이므로 그 파일은 아직 만들지 않았다.
- H2 저장 중 추가 입력, H3 미저장 보호, H5a 충돌 초안, M1 미래 반기 제한, M2 배점 오류, H1 업무 마감 구분은 설명 접기 대상으로 바꾸지 않는다.

## HelpCallout API와 상태 저장 제안

최소 API는 `ui.tsx`의 `HelpCallout`과 페이지 제목 옆 도움말 버튼이다. 별도 전역 provider나 서버 저장은 필요하지 않다.

```tsx
type HelpCalloutProps = {
  userId: string;
  id: string;                 // 위 표의 고정 ID, 제목·현재 필터로 만들지 않음
  summary: ReactNode;        // 승인된 짧은 안내
  children?: ReactNode;      // 기존 세부 의미를 보존한 설명
  reopenToken?: number;      // 페이지 도움말 버튼을 누를 때 증가
  className?: string;
  helpTriggerRef?: RefObject<HTMLButtonElement | null>;
};
```

- 페이지당 `helpToken`과 도움말 버튼 ref 하나면 충분하다. 버튼에는 `type="button"`, `aria-label="개인업무 도움말 다시 보기"`처럼 화면 이름을 넣는다. 아이콘만 사용해도 접근 가능한 이름은 제공한다. 처음 보는 사용자도 찾을 수 있도록 tooltip에만 설명을 의존하지 않는다.
- 교육용 콜아웃들에 같은 `reopenToken`을 전달한다. 버튼을 누르면 해당 페이지의 교육 설명을 다시 펼치고 각 키를 `expanded`로 저장한다. 다른 페이지·사용자의 키를 일괄 삭제하지 않는다.
- 저장 키는 원문대로 `ieum.help.<userId>.<id>`. 저장 값은 검증 가능한 문자열 `expanded | collapsed | dismissed`로 충분하다.
- 처음 방문하거나 키/값이 없거나 손상되면 `expanded`. 사용자가 접으면 `collapsed`를 기억하고 한 줄 요약과 펼치기 버튼을 남긴다. `다시 보지 않기`를 선택하면 `dismissed`로 해당 교육 콜아웃을 숨기되 제목 옆 도움말 아이콘은 항상 유지한다.
- 단순 방문만으로 자동 접힘 처리하지 않는다. 첫 방문 펼침과 사용자가 선택한 이후 상태 기억을 구분한다.
- 저장소 접근은 최초 읽기, 저장, 삭제가 필요하면 삭제까지 모두 try/catch로 감싼다. 상태는 먼저 React에서 변경하고 저장 실패는 조용히 무시해 기능을 유지한다. 실패를 alert로 표시할 필요가 없다.
- 서버 렌더나 초기 render에서 localStorage를 직접 읽지 않는다. 최초 상태는 동일한 `expanded`로 두고 effect에서 해당 사용자 키만 읽는다. 계정/ID가 바뀌면 이전 사용자 상태를 재사용하지 않는다. HelpCallout 자체에 `userId:id` key를 주는 것은 가능하지만 폼·페이지 전체 key를 바꾸면 안 된다.
- 저장은 사용자 동작에서만 수행한다. 처음 읽은 상태를 저장하는 effect를 두지 않아 초기 기본값이 기존 숨김 설정을 덮어쓰는 일을 막는다.
- `reopenToken`은 마운트 시 기존 숫자를 명령으로 해석하지 않고 실제 변경만 처리한다. 나중에 조건부로 나타나는 표 각주/반기 평가 각주는 자신의 저장 키를 정상적으로 읽는다.
- 접기 버튼에는 `aria-expanded`/`aria-controls`, 본문에는 `useId()`로 만든 안정적인 id를 제공한다. `다시 보지 않기` 후 버튼 자체가 사라질 때에는 `helpTriggerRef`로 포커스를 돌려 문서 body로 유실되지 않게 한다. 다시 열 때에는 도움말 버튼에 포커스를 유지해 강제 스크롤을 피한다.
- 도움말 상태는 업무 초안이 아니므로 dirty 등록·CommandFn·API 저장을 사용하지 않는다.

### 지표 범례 예외

5번은 교육용이지만 원문에서 짧은 범례를 **항상 화면에 표시**하도록 따로 요구했다. 공통업무 표/업무 목록 위에 `진행률: 절차 완료율 · 지연: 중앙 제출기한 기준`을 보이는 문장으로 남기고 `자세히`로 세부 설명을 연다. 구현 선택지는 다음 두 가지이며 첫 번째가 단순하다.

1. 범례 문장은 콜아웃 밖의 고정 영역, HelpCallout은 같은 줄의 `지표 기준 자세히` 접기 영역으로 둔다. 콜아웃을 숨겨도 범례는 남는다.
2. HelpCallout에 `keepSummary` 같은 명시적 속성을 추가해 해당 항목만 `dismissed`에서도 범례와 `자세히`를 남긴다.

수행 단계에 포함되는 상태, 미등록 0%를 포함한 배정 건별 평균, 지연 제외 상태, 업무 마감과 내부 회차 종료일의 차이, 단계 필터 전 집계 기준을 상세 설명에 보존한다. 역할·권한 제한은 아래의 실제 상태 메시지와 작업 화면에서도 계속 보여야 한다.

## 1440×900 목록 시작 위치 측정 기준

Root가 기존 합성 QA 화면에서 브라우저로 측정한다. 이번 조사에서는 DOM 좌표를 측정하지 않았으며 임의 px 수치를 보고하지 않는다. 측정 전후는 같은 시드, 역할, 화면, 필터, 선택 인물/반기, 데이터 건수를 고정한다. D1이 앞서 적용되므로 D2 직전 스냅샷을 D2 기준선으로 다시 잡는다.

| 화면·상태 | 1차 selector | 보조 selector·주의 |
|---|---|---|
| 개인업무, 전체 단위 | `.pw-task-groups` | 첫 실제 업무 `.pw-task-card`. 빈 단위 때문에 첫 업무 카드가 더 아래에 있을 수 있어 두 좌표를 구분한다. |
| 공통업무, 승인 목록 | `.cw-approval-list` | `.cw-approval-card` 첫 건. 승인 요청이 없으면 `.cw-approval-empty`를 측정하고 빈 상태라고 기록한다. |
| 공통업무, 업무별 보기 | `.cw-work-list` | `.cw-work-card` 첫 건. 승인 목록과 별개의 실제 배정 업무 목록 시작 위치다. |
| 공통업무, 전체 배정표 | `.cw-flat-table .cw-table-scroll` | `.cw-assignment-table`의 헤더 상단. 모바일에서는 `.cw-mobile-assignments`가 별도이므로 1440 기준 측정과 혼합하지 않는다. |

측정 방법:

1. 창 크기 1440×900과 브라우저 배율 100%를 고정한다. 팝업·검색·알림을 닫고 document 및 해당 스크롤 컨테이너를 0으로 둔다.
2. 폰트 로딩 완료와 React 화면 정착 후 두 프레임 이상 기다린다. HelpCallout 저장소 복원이 끝난 뒤 측정한다.
3. `getBoundingClientRect().top`을 viewport 기준 Y로 기록한다. 스크롤을 0으로 고정했으므로 문서 Y와 혼동하지 않는다. 필요한 보조값은 `top + window.scrollY`로 따로 표기한다.
4. `변경 전 / 변경 후 최초 펼침 / 변경 후 접힘 / 다시 보지 않기 / 도움말 다시 열기` 상태를 비교한다. 계정별 key만 초기화하고 다른 앱 저장소는 지우지 않는다.
5. selector가 없거나 display:none이면 0px로 처리하지 말고 `해당 없음` 또는 빈 상태 selector를 기록한다. 목록이 900px 아래여도 실제 Y값 그대로 남긴다.
6. 차이는 `이전 Y - 이후 Y`로 계산한다. 양수는 목록이 위로 이동한 거리다. 화면 전체 상자를 일괄 삭제한 효과가 아니라 상태·경고·버튼을 보존한 상태의 차이를 보고한다.

## 구현 시 필요한 검증

- 사용자 A의 접힘/숨김이 사용자 B에게 전파되지 않는다. 새로고침과 페이지 재방문에서 같은 사용자 선택이 유지된다.
- 최초 읽기·쓰기 예외, 잘못된 저장 값, 저장소 차단에서도 펼치기·접기·다시 보기가 동작한다.
- 첫 렌더의 기본값이 이미 저장된 dismissed를 덮어쓰지 않는다. 조건부 각주를 나중에 렌더해도 현재 page token만 보고 강제로 펼치지 않는다.
- 도움말을 숨긴 상태에서도 교육 상자 안에 있던 실행 버튼, 상태 수치, 잠금·권한 경고, 오류가 남는다.
- 키보드로 펼침·접힘·다시 보지 않기·제목 도움말 복구가 가능하고, 숨긴 뒤 포커스가 유실되지 않는다.
- 업무 입력 dirty 상태와 저장 중 추가 초안에 영향을 주지 않는다. 페이지/폼 key를 바꾸지 않는다.
- 1440×900 전후 Y 좌표를 실제 측정하고, 375px에서도 경고 문구·버튼·도움말이 가려지지 않는지 확인한다.
