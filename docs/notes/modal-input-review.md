# 등록·수정 팝업 텍스트 입력 오류 수정 (2026-11-08)

## 원인과 수정

- 기존 빌드에서 세부업무 등록 이름과 설명에 `Input test 123`, `Description test`를 한 글자씩 입력했으나 값이 빈 문자열로 돌아가는 현상을 재현했습니다. 입력창은 disabled/readOnly 상태가 아니었습니다.
- 공용 Modal의 `onInputCapture`가 매 입력마다 FieldErrors 컨텍스트를 갱신해, 제어 입력의 `onChange`가 값을 반영하기 전에 이전 값을 복원할 수 있었습니다.
- 오류 해제를 버블 단계의 `onChange`로 옮겨 입력창의 값 처리 뒤에 실행합니다. 해당 필드 오류가 없으면 같은 상태 객체를 유지하고, 중첩 팝업의 입력은 상위 팝업 오류를 지우지 않습니다.
- 필수항목 검증, 오류 포커스, 권한 제한과 미저장 종료 확인은 유지합니다.

## 검증

- 수정 전/후 모두 격리된 로컬 QA 서버와 합성 데이터로 확인했습니다. 운영 업무 데이터는 변경하지 않았습니다.
- 세부업무 등록: 빈 폼 제출로 오류를 표시한 뒤 영문·숫자 연속 입력, 전체 선택·삭제, 한글 입력, 설명 줄바꿈, 날짜 각 자리 입력과 반복 주기 선택을 확인했습니다. 수정한 필드 오류만 사라지고 나머지 오류는 유지됩니다.
- 실제 등록 후 상세 수정 화면을 다시 열어 입력값과 선택값을 확인하고, 설명을 추가 입력하여 저장했습니다.
- 단위업무 이름/목적 및 AI 업무등록 설명도 한글·영문 연속 입력을 확인했습니다. 미저장 종료 확인을 거쳐 초안을 닫았으며 AI 분석 호출은 하지 않았습니다.
- 공용 Modal 실제 핸들러를 사용하는 회귀 테스트 6개를 추가했습니다. 한글 조합 값 테스트는 전달된 값의 보존 검사이며 운영체제 IME 엔진 자체를 재현하는 테스트는 아닙니다.
- 전체 811개 테스트, 배포 빌드, TypeScript 검사 및 diff 공백 검사 통과.
