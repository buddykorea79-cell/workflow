# D3 · 보기 모드 텍스트 표시

2026-11-08. 개인업무 상세의 읽기 전용 값은 입력창 대신 공통 `ReadField`로 표시한다. 수정 권한과 저장 명령은 기존 조건을 유지한다.

## 적용 범위

| 위치 | 읽기 전용 표시 | 편집·초안 보존 경계 |
| --- | --- | --- |
| `ui.tsx` / `read-field.css` / `read-field-text.ts` | 라벨과 값, 빈 값 `미입력`, 줄바꿈 보존, 긴 문자열 줄바꿈, 안전한 HTTP(S) 링크, 날짜 전체 표기 | `data-read-label`과 `data-read-value`에는 표시용 가공 전 원문을 남긴다. 숫자 0을 빈 값으로 처리하지 않는다. |
| `personal-work.tsx` · TaskEditor 기본 정보 | 소속 단위업무, 세부업무 이름, 업무 마감일, 반복 주기, 업무 설명 | 현재 로컬 입력값을 사용한다. 기존 편집 모드와 단위업무 이동 권한을 유지하고 반복 주기의 중복 표시를 없앴다. 보기 안내는 실제 `업무 기준 수정` 버튼을 가리킨다. |

| `task-references.tsx` · TaskReferences | 근거 유형, 제목, 내용, 원문 링크, 연결한 파일명 | 근거별 `referenceEditable`과 `documentsOnly` 조건을 유지한다. 생산 문서 입력 모드에서 법령·지침은 읽기 전용이다. 파일 다운로드와 원문 열기는 유지한다. |

| `task-performance.tsx` · TaskPerformance | 타인/잠긴 성과 카드의 성과 내용 및 과거 근거 | 기존 지표와 참고 파일, 연도·반기 조회를 유지한다. 이전 작성 화면이 잠기면 `editorPeriod`를 통해 같은 편집기 인스턴스를 유지한다. |

## 유지한 동작

- 성과 작성 권한은 TaskEditor의 업무 기준 보기/수정 모드와 별도로 판단한다. 본인에게 작성 권한이 있는 반기 성과는 기존대로 편집할 수 있으며, D3에서는 `canWrite` 정책을 바꾸지 않았다.
- 업무·반기별 편집기 `key`와 마운트 구조를 유지했다. 잠김 상태 변화로 `description`, `attachmentIds`, 저장 기준 스냅샷을 재설정하지 않는다.
- 업로드 요청 중 읽기 전용으로 바뀌어도 `onChange`를 제거하지 않는다. 진행 중인 업로드가 완료되면 로컬 파일과 추가된 연결 값을 유지한다.
- 실제 업무 열람 권한을 잃은 경우의 상위 화면 잠금·다운로드 차단은 유지한다. 일반적인 읽기 전용 상태에서는 다운로드가 가능하다.
- 성과 · 평가 전체 화면의 기존 성과 목록, 업무 비중·평가 편집기 등은 이번 TaskEditor 보기 모드 변경 범위 밖이다. 안내 숨김 설정(D2), 충돌 확인(H5a), 미저장 확인(H3)도 유지한다.

## 검증

`tests/read-only-performance.test.ts`의 실제 컴포넌트 렌더 테스트 5개를 통과했다. 잠긴 성과의 텍스트·링크·다운로드, 잠김 뒤 유지된 미저장 텍스트·첨부와 복사 textarea, 편집 가능한 성과의 500자 입력·첨부 UI, 조회 기간·과거 지표 유지, 업로드 처리 중 파일·오류 표시를 확인한다. 유지된 상태 테스트는 React 로컬 상태를 주입한 렌더 회귀 테스트이며 실제 브라우저의 권한 전환을 실행한 테스트는 아니다.

관련 공통 필드·예산·근거·성과 첨부 권한 테스트 5개 파일에서 총 27개를 통과했고, `tsc --noEmit --incremental false`와 변경 파일의 `git diff --check`도 통과했다. 기본 sandbox 임시 폴더에서는 기존 첨부 경로 테스트 2개가 저장 오류로 실패하여, 테스트 전용 `.data/d3-test-temp`를 `TEMP`/`TMP`로 지정한 뒤 동일 27개를 재실행했다. 소스나 기대값을 바꾸지 않고 모두 통과했다. Neon 이름이 있는 테스트도 저장소 모의 응답을 사용한다.

통합 타입 검사·전체 678개 테스트·배포용 빌드가 통과했다. 운영 데이터나 외부 API는 사용하지 않았다.

### 실제 브라우저 확인

- 격리 QA의 업무 설명에 2,115자·50줄과 HTTP(S) URL을 넣었다. 마지막 줄까지 표시됐고 본문 높이와 스크롤 높이가 같아 내부 잘림이 없었다. 줄바꿈과 링크의 `noopener noreferrer`를 확인했다.
- 업무 개요의 비활성 텍스트 입력은 없어졌다. 남은 disabled 입력 1개는 화면에서 숨긴 파일 선택 input이다. 반복 주기는 한 번만 표시됐다.
- 보기→수정 시 단위업무 필드 위치는 동일했고 이름·마감·반복 주기의 세로 차이는 각각 0.5px·1.5px·1.5px였다. 가로 위치는 동일했다.
- 읽기 값은 흰색 배경의 `rgb(23,43,77)`로 대비 14.10:1, 빈 값은 `rgb(82,99,122)`로 6.13:1이었다. 두 값 모두 일반 본문 AA 기준 4.5:1을 넘는다.
- 375×812에서 본문 폭/스크롤 폭 375px, 상세창 345px, 설명 290px로 가로 넘침이 없었다. 긴 설명은 높이 2,184px로 전체 표시됐다.
- 예산·집행은 입력창 0개이며 전체 날짜·금액·미입력 표시를 확인했다. 관련 근거와 2027-H2 잠긴 성과의 본문도 텍스트로 확인했다. 현재 반기의 기존 독립 성과 작성 권한은 유지됐다.
- 화면 증빙: `.data/review-screenshots/d3-read-overview.jpg`, `d3-read-mobile.jpg`. 권한 전환 중 초안 보존은 이번 렌더 회귀 테스트와 앞선 H5a 실제 검증을 근거로 하며 D3에서 별도 실계정 권한 변경은 하지 않았다.
