# M5 알림 이동과 읽음 저장

- 신규 알림은 실제 대상 종류·ID와 생성 시각을 저장합니다. 공통업무 승인/반려는 공통업무, 부서·팀·개인 배정은 해당 배정, 인수인계는 구형 인계 또는 현재 이관, 성과·대행은 각각 해당 기록을 가리킵니다. 구자료는 기존 type·목적지·본문으로 해석합니다.
- 권한으로 제한된 워크스페이스에서만 대상을 찾습니다. 부서 담당자·관리자의 자기 부서 접수 대기는 배정·승인 화면, 다른 공통 알림은 공통업무 화면에서 해당 건을 찾습니다. 존재하지 않는 대상은 안전한 기본 화면으로 이동합니다.
- 대상 카드가 필터에 가려져 있으면 조회 조건을 해제하고 펼칩니다. 스크롤 후 2초 강조하며 키보드 초점을 연결합니다. 같은 알림을 다시 누르면 다시 강조하지만 일반 데이터 갱신은 필터를 초기화하지 않습니다.
- 기존 성과의 사람·반기 선택과 대행 요청 선택은 유지합니다. 해당 화면의 상세 선택 정보는 기존 컴포넌트 초기 선택으로 전달하며, 새 범용 focus 주소는 공통업무·배정·인수인계에 적용합니다.
- 알림 이동을 먼저 수행하고 읽음은 기존 직렬 명령 큐에서 백그라운드로 저장합니다. 전체 큐의 순서와 계정 검사는 유지하지만 읽음만으로 저장 중 표시, 성공 토스트, 입력 오류 초기화가 발생하지 않습니다.
- 지연된 읽음이 401로 실패하더라도 그사이 작성한 폼을 닫지 않습니다. 서버의 권한 검사는 그대로 적용하며 실제 읽음 저장은 실패 상태로 남습니다.
- 읽음 저장 실패는 같은 로그인 세션에서 다음 워크스페이스 조회 성공 시 재시도합니다. 브라우저 전체 새로고침은 메모리 대기를 초기화합니다. 저장되지 않은 알림은 서버에 읽지 않음으로 남으며 다시 클릭하면 처리합니다. 자동 재시도 반복 루프는 없습니다.
- 목록은 읽지 않은 알림을 먼저, 그 안에서는 생성 시각이 최신인 순서로 표시합니다. 시각이 없는 기존 기록에는 시간을 추정하지 않고 ‘이전 알림’을 표시합니다. 버튼 이름에 읽음 여부를 넣고 설명을 연결합니다.

자동·수동 검증 결과는 주 점검표에 기록합니다.
