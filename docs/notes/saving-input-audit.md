# H2 저장 중 입력 잠금 조사

TypeScript JSX 구문 트리로 `input`, `textarea`, `select`, `fieldset`의 `disabled`와 상위 컴포넌트의 잠금 전달을 조사했습니다. 단순 문자열 검색만으로 실행 버튼과 입력칸을 같이 해제하지 않습니다.

| 파일·영역 | 입력·탐색 처리 | 계속 제한할 동작 |
|---|---|---|
| workspace | 접근 코드, 상세 탭, 역할 전환의 명령 큐 | 중복 로그인·동일 제출 실행 |
| work-cycles | 수행 결과, 일정 날짜·메모, 회차 메모, 저장 중인 체크 외 다른 체크 | 완료·일시중지·권한 없는 절차, 저장 중인 해당 체크, 완료 실행 |
| personal-work | 개요, 예산 초안, 절차 수기 편집, 대행 선택, 상세 탭 | 파일 전송 중 중복 전송·저장, 권한·공통 필수 기준 |
| task-performance / unit-evaluation | 반기 선택, 성과 내용, 비중·평가 의견 | 제출·평가 확정, 저장·제출 실행, 진행 중 파일 전송 |
| common-work / allocation-review | 검토 의견·팀·담당자 선택 | 승인·반려·배정 실행 |
| personnel-handover / delegation-work | 인계·대행 선택 및 사유 | 권한 없음·기존 충돌 범위, 승인·요청 실행 |
| directive-monthly / directive-overview | 실적·지시자·일자 | 저장 실행, 읽기 권한만 있는 화면 |
| law-reference-picker | 검색어·종류·본문 필터 | 중복 외부 조회 실행, 편집 권한 없음 |
| procedure-builder / procedure-editor | 초안 자료와 절차 내용·순서 선택 | 중복 생성·추출·적용, 공통 필수 절차의 역할·이름 |
| task-references / task-file-attachments | 근거 내용과 이미 올린 파일 선택 | 진행 중 파일 전송의 중복 시작, 권한·파일 수 제한 |
| admin-integrations | 진단 조건 입력 | 진행 중 진단 실행·삭제 확인 토큰으로 고정된 대상 |

## 초안 보존 원칙

저장 요청에 보낸 값의 스냅샷과 응답 시점의 입력값을 비교합니다. 요청 뒤 입력이 더 생겼다면 성공 응답으로 창을 닫거나 그 입력을 지우지 않습니다. 서버에서 정규화된 값은 사용자가 추가로 바꾸지 않은 필드만 반영합니다. 같은 생성 요청을 다시 보내지 않도록 새로 생성된 업무·단위업무는 이후 저장의 수정 대상으로 연결합니다.

완료·승인 요청처럼 저장 성공으로 편집 권한이 달라지는 경우에도, 응답 대기 중 추가로 쓴 내용은 별도로 보존하고 어떤 값까지 저장됐는지 안내해야 합니다.

## 검증

- 독립 명령 큐: 순서·실행 시점 revision·중간 실패 뒤 계속 처리·역할 전환 순서를 검증하는 3개 테스트 통과.
- 위 표의 입력·탐색 잠금 해제와 구조·실행 잠금 분리를 적용했습니다. JSX 구문 및 입력 속성 전수 검사, 전체 459개 테스트, 타입 검사, 배포용 빌드를 통과했습니다.
- 실제 응답을 3초 지연하여 체크 4개의 연속 저장, 저장 중 수행 결과 입력, 완료 요청 뒤 추가 입력 보존 및 보완 메모 저장, 새로고침 뒤 영속 상태를 확인했습니다.
- 승인 요청 성공으로 더 이상 수정할 수 없는 기록은 추가 초안을 화면에 보존하고 접수 시점과 미반영 내용을 구분합니다. 자동 재제출은 하지 않습니다.
- 늦은 조회·첨부 응답은 현재 사용자·세션 세대·revision을 검사하여 새 저장과 역할 전환 결과를 덮지 못하도록 했습니다.
