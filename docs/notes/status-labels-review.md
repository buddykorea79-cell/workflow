# M4 상태 표시 통일 검토

## 기존 판정 차이

| 조건 | 개인업무 | 부서 업무 | 통일 기준 |
|---|---|---|---|
| 회차 없음·진행률 0 | 기준 상태(작성 중·확정 등) | 시작 전 | 실행은 시작 전, 기준 상태는 별도 보조 표시 |
| scheduled·진행률 0 | 예정 | 시작 전 | 시작 전 |
| scheduled·진행률 50·다음 담당자 | 예정 | 진행 중 | 실제 수행 기록이 있으므로 진행 중 |
| 다음 절차가 검토자·진행률 50 | 검토 대기 | 진행 중(run.status가 review가 아니면) | 검토 대기 |
| paused·진행률 100 | 일시 중지 | 일시 중지 | 명시적 일시 중지를 우선 |
| 진행률 100 | 완료 | 완료 | 완료 |
| 기준 변경 중·수행 미시작 | 수정 중 | 시작 전 | 시작 전 + 기준 변경 중 |

대시보드의 기존 `progress < 100` 집계에는 시작 전 업무도 포함됩니다. 실행 상태가 진행 중 또는 검토 대기인 건수만 주 수치로 집계하고 시작 전 건수를 설명에 표시합니다. 마감 임박 집계는 미완료 전체에서 별도로 계산해 시작 전 업무가 누락되지 않게 합니다.

용어와 색상은 `status-labels.ts`를 기준으로 연결합니다. 업무 기준 상태와 수행 상태, 공통업무 배정 단계는 서로 다른 개념으로 유지합니다. 인사이동의 예약 시점과 대행 시작 예정은 업무 수행 상태가 아니므로 별도 문맥입니다.

## 용어 점검 범위

개인·부서·공통업무·배정·회차 화면과 홈 집계를 공통 판정에 연결합니다. 업무 알림/오류, 메뉴, 역할 전환, usage-guide, README, USER-GUIDE의 업무 배부는 배정으로 변경합니다. 이번 검색 범위에는 제외해야 할 예산 배부 문맥이 없었습니다.

`status-terminology.test.ts`는 컴포넌트의 배부·보류·검토 중·예정을 검사합니다. 기준 검토 중은 별도 기준 상태이며, 대행의 승인·시작 예정, 인사이동 예약, 기존 이력의 예정 결과물은 업무 수행 상태가 아니므로 명시적으로 허용합니다.
