# AI 업무 등록: 분석 서버

## 범위와 계약

`POST /api/work-registration`은 등록할 업무 초안을 만드는 읽기 전용 경로다. Node.js Route Handler이며 최대 실행 시간은 70초, 분석 작업의 시간 예산은 60초다. 설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`를 확인했다. 실제 업무 저장은 별도의 `work.import` 명령이 담당한다.

파일은 기존 `uploadAttachment`의 본인 임시 업무 식별자(`draft:<userId>:<UUID>`)로 업로드한다. 배포 환경에서는 기존 서명 PUT 경로를 사용하여 10MB 파일을 함수 요청 본문에 직접 보내지 않는다. 새 경로는 multipart 또는 외부 URL을 받지 않는다.

| 작업 | JSON 요청 | 응답 |
| --- | --- | --- |
| 본문 추출 | `{action:'extract', attachmentId}` | `{document:{attachmentId,name,text,format,pageCount?,pages?,warnings}}` |
| 초안 생성 | `{action:'generate', description, documents:[{attachmentId,text}]}` | `{preview:{units:[{title,description,tasks:[{title,description}]}]},model}` |

분석 문서 이름은 저장된 첨부 정보에서 가져온다. 생성 요청의 본문은 사용자가 추출 후 수정한 텍스트여도 된다. 문서 없이 설명만 입력할 수도 있다. 날짜·주기·우선순위·담당자·부서·근거 ID는 생성 결과에 없다. 화면이 빈 마감일과 기본 주기·우선순위를 붙이고 사용자가 확인한 뒤 등록한다.

## 제한 및 권한

- 요청은 실제 수신한 UTF-8 바이트 기준 350,000바이트까지 읽는다. `Content-Length` 누락이나 작은 값으로 위조해도 제한한다. 알 수 없는 JSON 속성, 중복 문서 ID, 빈 분석 입력을 거절한다.
- 문서는 최대 10개, 설명과 문서 본문 합계는 60,000자다. 첨부는 파일당 10MB이며 PDF/HWP/HWPX/DOCX/XLSX/XLS/PPTX/TXT/CSV를 허용한다. 기존 `extractDocument`의 150쪽·섹션, 추출 본문 20만 자, OCR 및 자동 모델 다운로드 금지 정책을 재사용한다. 6만 자를 넘는 추출 결과는 화면에서 필요한 부분으로 줄인 뒤 생성할 수 있다.
- 활성 사용자, 실제 소속 부서, 부서 업무분장 편집 가능 여부를 확인한다. 부서장은 거절한다. 관리자도 타인의 임시 첨부를 읽을 수 없다.
- 첨부의 임시 식별자와 `uploadedBy`가 모두 본인과 일치해야 한다. 기존 업무 첨부, 성과 첨부, 없는 첨부는 거절한다. 추출할 실제 바이트의 크기와 SHA256도 저장 정보와 비교한다.
- 분석이 끝난 뒤 최신 상태를 다시 읽어 계정·소속 부서 편집 권한과 파일 소유권을 재검사한다. 분석 중 파일 이름·저장 키·해시·업무 연결 등이 바뀌면 결과를 반환하지 않는다. 분석 경로에서는 업무·첨부 연결·감사 이력·revision을 변경하지 않는다.
- 사용자당 동시 분석 1건, 추출 20회/분, 생성 5회/분이다. 생성은 기존 모든 유료 AI 경로와 공유하는 `assertUserRateLimit`도 소비한다. 추출은 10파일 일괄 처리 후 생성이 가능한 별도 한도를 쓴다.

## AI 응답과 실패

`bizrouter.ts`의 공유 구조화 전송 helper를 사용한다. 허용 모델 목록 및 JSON schema 지원 확인, 고정 HTTPS 대상, 리디렉션 거절, 카탈로그 8MB·완성 응답 1MB 제한을 기존 정책과 공유한다. 새 생성 경로에는 숨은 자동 재시도가 없다. 사용자가 오류를 확인한 뒤 다시 분석한다.

AI 출력은 단위업무 1~10개, 전체 업무 1~30개, 단위업무명 100자, 업무명 150자, 설명 각각 5,000자, 이름과 설명 합계 60,000자를 엄격히 검증한다. 각 객체는 허용된 필드만 받는다. 프롬프트는 문서를 신뢰할 수 없는 데이터로 취급하고 원문에 없는 사람·부서·기관·법령·의무·일정을 만들지 않도록 지시한다. 이 구조 검증이 설명 안의 모든 사실을 입증하는 것은 아니므로 등록 전 사용자 검토는 필요하다.

한도·형식·권한 오류와 제공자 오류는 한국어 메시지와 오류 코드로 응답한다. 키, 원문 전체, 제공자의 오류 본문은 로그나 오류 응답에 넣지 않는다. 입력은 서버가 지우지 않으며 화면이 실패 시 초안을 유지한다.

## 검증 및 남은 운영 한계

`tests/work-registration-generation.test.ts`는 strict 입력/출력, 역할·소유권, 바이트 무결성, 최신 상태 재검사, 동시 실행, 사용자별/공유 한도, 중단, 구조화 모델 요청·응답 한도를 검증한다. `tests/work-registration-route.test.ts`는 임시 로컬 저장소에서 인증/출처/실제 수신 크기, 실제 HWPX Kordoc 추출, 모의 BizRouter 응답, 분석 전후 데이터 불변을 검증한다. 운영 DB·저장소·AI에는 연결하지 않았다.

기존과 같이 한도 및 동시 실행 집계는 프로세스 메모리 단위다. 여러 서버 인스턴스 전체의 엄격한 비용 제한이 필요하면 공유 저장소 기반 제한이 별도 필요하다. Kordoc은 중단 신호를 받지 않으므로 요청 취소/시간 초과 뒤에도 이미 시작한 파서는 종료될 때까지 실행될 수 있다. 해당 사용자 동시 실행 잠금은 실제 작업이 끝날 때까지 유지하며, 동기 파서 내부를 강제로 종료하지는 못한다.

분석용 임시 첨부의 보관·삭제 정책은 기존 업로드 정책을 유지한다. 취소한 분석의 파일을 자동 삭제하거나 업무에 자동 연결하지 않는다. 초기 preview만으로 업무 등록 성공을 의미하지 않으며 `work.import`가 최신 권한과 전체 입력을 다시 검증해야 한다.
