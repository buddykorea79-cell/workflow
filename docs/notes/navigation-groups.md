# D7 역할별 사이드바 그룹 검증

2026-11-08. [승인된 메뉴 제안](../design/review-proposals-2026-11-07.md)의 네 그룹을 현재 화면 권한과 대조했다. 서버 권한·조회 범위는 변경하지 않으며 기존 상단의 업무분장표 바로가기를 유지한다.

표의 화면 수는 사용 안내·프로필·상단 바로가기의 중복을 제외한 고유 목적지 수다. 업무분장표는 기존에도 모든 역할이 상단에서 조회할 수 있었으며, 이번에 사이드바에서도 같은 목적지에 접근하게 한다. 부서장의 개인업무 제외, 부서 업무의 부서장·관리자 제한, 배정 승인의 부서 담당자·관리자 제한, 부서 예산의 부서 담당자·부서장·관리자 제한, 관리자 화면 제한을 유지한다. 메뉴가 보인다고 추가 승인 권한을 부여하지 않는다.

## 펼침과 처리 대기

- 내 업무는 항상 펼친다.
- 첫 표시 시 협업·부서 관리는 현재 화면이 있거나 처리 대기가 있으면 펼친다.
- 조직·시스템은 기본으로 접으며, 현재 화면이 그 안에 있으면 선택한 위치를 확인할 수 있도록 펼친다.
- 사용자가 접은 상태는 같은 화면·같은 합계로 다시 조회해도 유지한다. 실제 화면이 바뀌면 새 현재 화면이 있는 그룹을 펼친다. 협업·부서 관리의 처리 대기 합계가 증가하면 해당 그룹을 펼친다.
- 사용자 또는 역할 전환 시 이전 사람의 수동 펼침 상태를 가져오지 않고 해당 역할의 초기값으로 설정한다.
- 펼친 그룹의 메뉴에는 M6의 처리 대기 배지를 유지한다. 접힌 그룹 제목에는 그 그룹에서 볼 수 있는 메뉴의 합계만 표시한다. 다른 역할 전용 목적지의 수치는 합산하지 않는다.
- M6의 부서 담당자·관리자 배정 대기는 본인 부서 기준이며 전체 부서의 총계로 해석하지 않는다. 인수인계·성과·대행도 기존 실제 처리 권한과 배치 단위 집계를 유지한다.

## 접근성과 화면 검증 범위

각 그룹은 `role="group"`과 고유 제목을 `aria-labelledby`로 연결한다. 접기 버튼은 실제 `aria-expanded` 상태와 내용 영역의 `aria-controls`를 제공하며 숨긴 메뉴는 키보드 탐색에서도 제외한다. 메뉴의 현재 위치는 `aria-current="page"`로 남기고 키보드 활성화는 기존 탐색·미저장 변경 확인을 거친다. 모바일도 같은 그룹 데이터를 사용한다. 사용 안내와 프로필은 하단에 남긴다.

1440×900 검증에서는 **기본으로 접힌 그룹 제목과 펼쳐진 메뉴·하단 도구가 화면 안에 들어오는지**를 측정한다. 이는 모든 그룹의 모든 하위 메뉴가 동시에 보인다는 뜻이 아니다. 현재 화면이나 처리 대기로 여러 그룹이 펼쳐지거나 사용자가 전부 펼치면 필요한 세로 스크롤을 허용하며 메뉴를 잘라 숨기지 않는다. 375px에서는 같은 접근 경로와 가로 넘침 여부를 별도로 확인한다. 실제 측정 전에는 높이 목표를 달성했다고 기록하지 않는다.

## 자동 검증

`tests/navigation-groups.test.ts`는 실제 시드의 다섯 역할 워크스페이스를 기존 접근 계약과 대조하고, 실제 공통업무 승인 요청에서 계산된 M6 배지를 그룹 합계에 연결한다. 정확한 목적지 집합·중복·역할별 제한, 현재 화면의 초기 펼침, 수동 접힘 보존, 실제 화면 변경, 대기 증가·동일 합계·감소, 유효하지 않은 배지 수치를 점검한다.

신규 7개 테스트와 기존 M6 배지 7개 테스트, 통합 타입 검사 및 diff 검사를 통과했다. 실제 컴포넌트 렌더에서 네 그룹의 제목 연결·고유 ID·숨긴 메뉴·현재 위치를 확인했다. 실제 콜백으로 수동 접힘의 배지 합계, 같은 데이터 재조회 후 접힘 보존, hover/focus의 코드 미리 불러오기, 탐색 수락을 root 콜백에 위임하는 계약과 계정·역할 변경 시 상태 초기화 경계를 확인했다. 기존 테스트 기대값은 변경하지 않았다. 1440×900·375px 실제 화면과 키보드 검증 결과는 통합 빌드 수동 확인 후 추가한다.

## 실제 화면 검증 (2026-11-08)

전체 723개 테스트, 타입 검사, 배포용 빌드를 통과했다. 1440×900에서 업무 담당자·팀장·부서 담당자·부서장·관리자 모두 기본 메뉴의 clientHeight와 scrollHeight가 560px로 같았다. 처리 대기가 있는 협업 그룹은 펼쳐지고 계정 전환 시 이전 접힘 상태가 초기화됐다. 관리자 협업의 개별 2+1건은 접으면 3건, 부서장의 1+1건은 2건으로 표시됐다.

375×812에서 동일 그룹의 Enter/Space 접기·펼치기, 파란 2px 키보드 초점, 숨긴 메뉴 제외를 확인했다. 본문 scrollWidth 360px로 뷰포트 375px를 넘지 않았다. 모든 하위 메뉴를 동시에 펼쳤을 때는 메뉴 영역 안에서 스크롤하며 하단 도구는 유지한다. 임시 화면 크기는 검증 후 복구했다.
