# D4 · 탭 접근성 및 필터 분류

2026-11-08. C2에서 제거한 미사용 `task-detail.tsx`의 탭·패널 의미 연결을 공통 `Tabs` / `useTabs`로 옮긴다. 기존 컴포넌트에 없었던 키보드 처리를 함께 제공하며, 외형에 `tabs` 클래스가 있다는 이유만으로 필터를 탭으로 바꾸지는 않는다.

## 공통 계약

- 탭 목록은 `role="tablist"`, 목적을 설명하는 `aria-label`, 가로 방향을 사용한다.
- 각 버튼은 `role="tab"`, 인스턴스별 고유 `id`, `aria-selected`, 해당 패널의 `id`를 가리키는 `aria-controls`를 갖는다.
- 패널은 `role="tabpanel"`과 탭을 가리키는 `aria-labelledby`를 갖는다. 선택하지 않은 패널도 빈 `hidden` 컨테이너로 남겨 `aria-controls` 대상이 항상 존재하게 한다. 보이지 않는 편집기를 새로 마운트하지 않는다.
- 선택된 가용 탭만 `tabIndex=0`, 나머지는 `-1`이다. 좌우 방향키와 Home/End는 가용 탭의 초점만 이동하고 Enter/Space 또는 클릭이 선택을 요청한다. 끝에서는 순환하며, 가용 탭이 하나여도 처리한다.
- **수동 활성화**를 사용한다. 방향키 탐색만으로 미저장 확인창을 열거나 패널의 폼을 바꾸지 않으며, 사용자가 선택할 때 기존 화면의 미저장 가드를 거친다. 공통 컴포넌트는 선택 상태를 내부에서 먼저 바꾸지 않는다.
- `busy`나 업로드 진행 여부로 탭을 막지 않는다. 없는 과거 회차처럼 구조적으로 선택할 내용이 없는 항목만 비활성화한다.
- 탭과 패널 모두 `:focus-visible` 외곽선을 갖는다. 긴 탭 목록은 가로 스크롤할 수 있다.

## 회차·초안 보존

`work-cycles.tsx`는 기존 본문을 안정된 활성 패널 컨테이너로 감싸고 반대 탭의 빈 숨김 패널을 별도로 둔다. `CycleScheduleForm`, `CurrentCycleSteps`, `CurrentCycleNotes`, `CycleHistory`, 전달된 `children`의 조건부 렌더와 기존 `key`를 유지한다. 현재 회차 안에서 일정 모드나 저장 상태가 갱신될 때 탭 패널 때문에 입력기가 재생성되지 않는다. 실제 회차 선택은 종전처럼 미저장 확인 후 전환한다. `displayedRunId`와 최신 회차 안내·초안 보관 정책도 변경하지 않는다.

## 검증과 한계

`tests/work-cycle-tabs.test.ts` 신규 6개는 실제 컴포넌트 렌더로 탭·패널 양방향 연결, 비활성 패널 존재, 1개 가용 탭, 미저장 상태에서도 탭 사용 가능, 현재/과거의 선택된 콘텐츠, 일정 편집 중 구조, 인스턴스별 고유 ID, 반기 필터와 미래 반기 제한을 확인한다. 상태를 주입한 렌더 검증이며 브라우저에서 선택 이벤트나 확인창을 조작한 검증과는 구분한다.

신규 6개와 기존 회차·회차 메모·성과 읽기 테스트를 합쳐 26개 통과했다. 공통 키보드 helper와 `Tabs` 자체의 이벤트·초점 검증은 별도 공통 테스트에서 다룬다. 실제 키보드 초점, 확인창 취소·승인 후 이동, 모바일 가로 스크롤, 스크린리더 발화는 통합 빌드에서 가능한 범위를 확인하고 미실행 항목은 완료로 기록하지 않는다.

### 통합·실제 키보드 검증

- 타입 검사, 전체 695개 테스트, 배포용 빌드가 통과했다. 기존 알림 이동 테스트 2개가 예전 aria-pressed를 기대하여 실패한 원인을 먼저 보고한 뒤, 실제 탭의 aria-selected를 확인하도록 선택 상태 assertion 4곳만 바꿨다. 대상 카드·부서·이동·초안 기대는 그대로 유지했다.
- 실제 브라우저에서 업무 개요→절차→일정·수행→성과→관련 근거→예산·집행의 6개 탭을 방향키+Enter로 순회했다. 방향키/Home/End만 누르면 선택 화면은 유지되고 초점만 이동했다. Space로도 선택됐다.
- 성과에 합성 초안을 입력한 뒤 Home으로 업무 개요에 초점을 옮겨도 확인창이 열리지 않았다. Enter에서만 미저장 확인이 표시됐다. Esc 취소 후 성과 선택·초안이 보존되고 초점은 요청한 업무 개요 탭으로 복귀했다. 명시 폐기 후에는 업무 개요로 이동했다. 시험 초안은 저장하지 않았다.
- 375×812에서 탭 영역은 290px/내용398px의 내부 스크롤이며 End 이동한 마지막 탭 오른쪽이321.47px로 화면 안에 드러났다. 본문375px/스크롤375px로 가로 넘침이 없었다. 6개 제어 대상 패널이 모두 존재했다.
- 키보드 초점 외곽선은 파란색2px였다. 실제 공통업무의 두 탭 그룹과 인수인계도 키보드 선택 및 해당 패널 표시를 확인했다.
- 스크린리더가 사용하는 DOM/접근성 스냅샷에 tablist·tab·selected·tabpanel 연결을 확인했다. NVDA 음성 출력은 직접 실행하지 않았으며 음성 검증 완료로 주장하지 않는다. 관리자·배정·지난 회차의 세부 전환은 자동 렌더/콜백 검증을 근거로 한다.
