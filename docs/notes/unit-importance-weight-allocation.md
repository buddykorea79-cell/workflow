# 중요도에 따른 성과 비중 배분

신규 계획은 단위업무 중요도 1~10을 이용해 합계 50점의 정수 비중을 제안한다. 중요도 누락·이상값은 5로 읽으며, 저장된 비중이나 제출·평가 기록을 중요도 변경만으로 다시 계산하지 않는다. 기존 계획의 0점·소수 비중도 초기 입력에 그대로 보존하고, 새 저장은 모든 단위업무에 1점 이상을 배정해야 한다. 50개를 초과하면 최소 1점 조건과 합계 50점을 동시에 충족할 수 없어 자동 배분과 새 저장을 차단한다.

50개 제한은 해당 반기의 평가 대상 전체에 적용한다. 과거 계획에 포함된 단위업무는 현재 목록에서 삭제·이동해도 이력 보존을 위해 평가 대상에 남을 수 있으므로, 현재 단위업무 구성을 줄이면 해결된다고 안내하지 않는다. 기존 51개 계획에 1점 50개와 0점 1개가 있다면 마지막 단위를 삭제해도 새 배분·저장은 제한되지만, 기존 계획·성과는 그대로 보관하고 기존 규칙에 따른 제출·평가를 유지한다.

알고리즘은 남은 점수와 중요도의 비율로 계산한 몫이 1점보다 작은 항목을 먼저 1점으로 고정한다. 고정된 항목과 점수를 제외하고 이 판정을 반복한다. 나머지는 정수 나눗셈의 몫을 배정한 뒤, 나머지가 큰 순서로 남은 점수를 1점씩 배정한다. 나머지가 같으면 기존 단위업무 순서를 유지한다. 부동소수 비율 대신 정수 분자와 나머지를 사용한다.

예: 중요도 10·5·1은 31·16·3점이다. 중요도 1인 업무 44개와 중요도 10인 업무 1개는 44개에 각각 1점, 중요한 업무에 6점을 배정한다. 모든 업무에 먼저 1점을 나눠 주고 나머지만 비례 배분하면 중요한 업무의 비율이 과도하게 줄어들므로 그 방식은 사용하지 않는다. 업무가 정확히 50개이면 모두 1점이다.

화면에는 중요도와 자동 배분 제안을 현재 입력값 옆에 표시한다. ‘중요도 기준으로 다시 배분’을 누르고 확인해야 현재 입력값을 교체하며, 확인 중 단위업무·중요도·제출 상태가 바뀌면 적용을 중단한다. 재배분 후에도 저장 전에 직접 수정할 수 있다. 저장 중 추가 입력, 미저장 보호, 기존 대상별 충돌 검사를 유지한다.

검증: `weight-validation` 7개, `importance-weight-allocation` 6개, `importance-weight-editor` 5개. 합계·최소값·50개 경계·동률 순서·하한 반복 적용, 기존 0점/소수 보존, 명시 재배분 취소/승인, 최신 상태 변경, 첫 저장 중 닫기 보호와 추가 입력 보존을 검사한다. 실제 부서장 평가 점수와 기존 계획의 제출·평가 호환성은 서버의 별도 회귀 검사 범위다.

## 기존 데이터와 통합 검증

기존 단위업무의 중요도는 조회 즉시 5로 적용한다. 조회만으로 원본 JSON이나 Neon 데이터를 다시 쓰지 않고, 다음 실제 업무 변경 트랜잭션에서 기본값을 함께 저장한다. 과거 평가 스냅샷과 대상별 수정 버전은 기본값 적용만으로 변경하지 않는다. 새 업무·AI 등록은 5로 시작하고 인수인계로 복사한 업무는 기존 중요도를 유지한다.

2026-11-08 전체 회귀 테스트 794개를 통과했다. 타입 검사, 배포 빌드, CSS 감사도 확인한다. 별도 로컬 QA 저장소에서 기본값 5, 잘못된 중요도 저장 거절, 생성·수정·새로고침 후 중요도 내림차순과 동률 순서 유지, 정수 합계 50점 제안, 수동 배점 저장·재열기, 재배분 취소·적용, 0점·소수 저장 차단을 확인했다. 375px 화면에서 접근 화면과 평가창의 가로 넘침이 없으며 접근 코드 입력칸과 버튼의 기본 간격은 20px이다. 검증 중 운영 데이터와 외부 AI는 사용하지 않았다.
