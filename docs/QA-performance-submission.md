# 업무 성과·제출·관련근거 검증 · 2026-11-01

- 세부업무 마지막 업무 성과 탭에서 반기별 성과 작성·수정·저장. 성과 · 평가에서 단위업무별로 집계.
- 모든 활성 단위업무의 업무 비중 합계는 50점. 양수 비중의 단위업무에는 완성된 성과가 필요하고, 0점 업무는 성과 없이 제출 가능.
- 성과 저장과 제출하기는 별도 동작. 제출 전 평가, 타인 제출, 제출 후 성과·비중 변경, 평가 확정 후 회수는 서버에서 차단.
- 부서 담당자는 같은 부서 직원의 제출 상태·일시만 추가로 조회하며 타 직원의 반기 성과 본문·업무 비중·평가 점수는 노출하지 않음.
- 관련근거는 새 입력란 하나로 시작하고 추가·파일 첨부·연결 해제를 지원. 빈 입력란은 저장하지 않으며 기존 근거는 유지.

## 검증 결과

- `npm run typecheck` 통과.
- `npm test` 전체 157개 통과.
- `npm run build` 운영 빌드 성공.
- 격리한 `.qa/performance-submission-20261101` 저장소와 3001 포트에서 `tests/http-unit-evaluation.mjs` 11개 확인 통과: 저장/제출 분리, 50점·상한·버전 검증, 권한, 잠금, 평가 결과 보존, 부서 담당자 제출 상태 조회.
- 같은 격리 환경에서 `tests/http-procedure-schedule.mjs` 7개 확인 통과: 근거 파일 업로드·연결·재조회, 일정과 회차 수행 회귀.
- 실제 브라우저에서 업무 성과 탭 입력·저장, 단위업무별 집계, 비중 저장 후 제출하기 활성화, 제출 후 수정 잠금, 부서 담당자의 미제출/제출 완료/평가 완료 표시를 확인.
- 관련근거 컴포넌트 렌더 확인: 빈 입력란 1개, 추가·첨부 버튼, 기존 여러 근거 보존.
- 마지막 빌드는 Windows 파일 접근 제한을 해소한 뒤 성공했으며, 기존 데이터 경로로 3000 포트의 앱을 재실행하고 HTTP 200 응답을 확인했다. 3001 포트 검증 서버는 종료했다.

기존 `.data/workspace.json`을 복사한 격리 저장소에서만 검증 데이터를 변경했다. 새 제출 상태는 기존 업무 비중 JSON에 선택 필드로 저장하므로 별도 데이터 마이그레이션이 필요하지 않다.
