# 업무분장표와 다운로드

모든 로그인 역할은 **먼저 소속 부서의 업무분장표**를 조회합니다. 관리자도 같은 기본값을 사용합니다. 부서 선택 목록에서 다른 부서의 업무명과 담당 관계를 조회하고, 관리자는 **전체 부서**도 선택할 수 있습니다. 부서장·관리자의 기존 업무분장 관리 화면은 확정·재작성 등 관리 기능을 계속 제공합니다.

## 화면과 표시 기준

- 화면 상단 검색 옆의 간단한 아이콘·글자 **업무분장표**로 엽니다. 별도 박스 없이 주변 메뉴와 같은 스타일을 사용합니다.
- 담당자 → 단위업무 → 세부업무 → 업무대행자를 표시합니다. 업무 코드는 표시하지 않습니다.
- 모든 역할이 부서·팀·담당자 이름으로 조회 조건을 설정할 수 있습니다. 이름은 원 담당자 이름을 검색합니다. 부서 변경 시 팀 조건은 전체 팀으로, 초기화 시 부서는 소속 부서·팀은 전체 팀·이름은 빈칸으로 돌아갑니다.
- 업무대행을 승인해도 원본 업무를 복제하지 않습니다. 원 담당자의 업무 행에 현재 유효한 대행자 이름이 추가됩니다.
- 대행 승인 대기·반려·종료·취소, 대행 시작 전·종료 후의 사람은 현재 업무대행자로 표시하지 않습니다.
- 삭제·보관된 세부업무, 삭제된 단위업무, 개인업무에 등록되지 않은 공통업무는 제외합니다.
- 분장표에는 업무 제목과 담당 관계를 공유합니다. 세부업무의 **절차도 보기**에서는 현재 저장된 업무 기준의 단계명·역할·선행 관계와 배정된 담당자 이름을 추가로 조회합니다.
- 업무·절차 상세 설명, 예산·성과·연락처·첨부파일·문서 내용, 일정 날짜와 완료 기록은 제공하지 않습니다. 업무분장표와 절차도 조회가 원본 업무 상세의 접근·수정 권한을 추가하지 않습니다.
- 업무 담당자 1(송주무관)과 업무 담당자 2(조주무관)는 모두 데이터정보화담당관실 분장표에서 시작합니다. 두 시연 선택 항목 모두 실제 권한은 업무 담당자입니다. 다른 부서의 분장표를 선택해도 업무 본문·성과·첨부파일 접근 권한은 추가되지 않습니다.

## 세부업무 절차도 보기

세부업무 옆 **절차도 보기**를 누릅니다. 모든 활성 로그인 역할에서 현재 분장표에 표시되는 업무의 절차도를 조회할 수 있으며 다른 부서의 업무도 같은 기준을 적용합니다.

팝업의 **업무절차도** 제목 아래에는 **부서명: … · 단위업무: … · 개인업무: …**를 한 줄로 표시합니다. 본문에는 목록·범례·사용 설명 없이 절차도만 표시합니다.

절차도는 **담당자·협업 지원·검토 역할을 세로 행**, **진행 순서를 왼쪽에서 오른쪽**으로 배치합니다. 단계명은 카드에, 현재 업무 기준에 배정된 이름은 역할 행의 왼쪽에 표시하고 선행 관계는 화살표로 연결합니다. 세로 높이는 창에 맞추며, 긴 흐름은 확대·축소 조작 없이 **가로 스크롤**로 확인합니다. 저장된 절차가 없으면 절차 없음 안내를 표시합니다. 특정 회차의 진행률·일정·완료 여부나 과거 수행 이력을 나타내는 화면은 아닙니다.

조회 버튼을 누를 때 서버에서 최신 데이터를 읽고 해당 업무가 분장표에 표시되는 대상인지 다시 확인합니다. 삭제·보관되었거나 분장표에서 제외된 업무는 주소의 업무 식별자를 바꾸어도 조회할 수 없습니다. 이 조회 과정은 원본 업무와 수행 기록을 변경하지 않습니다.

## 업무대행 범위 선택

**업무대행 → 업무대행 요청**에서는 같은 네 열의 분장표에 체크박스를 제공합니다. 원담당자의 전체 업무, 단위업무 전체 또는 세부업무 일부를 선택합니다. 조회용 업무분장표에서 체크하는 방식이 아니라 업무대행 요청 안의 선택표를 사용합니다.

선택한 원담당자 한 명의 최대 300개 세부업무를 대행자·기간·사유가 같은 요청으로 묶습니다. 부서장은 요청 상세의 전체 목록을 함께 승인하며, 승인 당시 유효하지 않은 업무가 있으면 전체 승인이 중단됩니다. 이후 추가된 업무는 기존 요청에 자동 포함되지 않습니다. 승인된 유효 기간에만 현재 업무대행자 열에 표시됩니다.

## Excel·PDF 내려받기

화면 위 **Excel 다운로드** 또는 **PDF 다운로드**를 누릅니다. 모든 역할에서 현재 선택한 부서·팀·이름 조건을 적용해 서버의 최신 데이터로 파일을 생성합니다. 다운로드 도중에도 원본 업무 데이터는 변경하지 않습니다.

- Excel: 실제 `.xlsx` 파일이며 담당자·단위업무를 묶어 표시하고, 각 행의 내용을 문자열로 저장합니다.
- PDF: 한글 글꼴을 포함한 가로 A4 문서입니다. 부서별 구분, 반복되는 표 머리글, 긴 제목의 여러 페이지 이어쓰기를 지원합니다.
- 절차도는 화면에서 별도로 조회하며 Excel·PDF에는 기존 분장표 항목만 포함합니다.
- 새 인증 변수나 외부 문서 변환 서비스는 필요하지 않습니다. 기존 로그인과 DB 연결을 사용합니다.

## 구현 경로

| 역할 | 파일 |
| --- | --- |
| 업무 제목·담당 관계만 담는 최소 조회 모델 | `src/lib/organization-division.ts` |
| 화면과 조회 조건 | `src/components/organization-division.tsx` |
| 파일 생성 | `src/lib/organization-division-export.ts` |
| 인증된 실제 파일 다운로드 | `GET /api/organization-division/export` |
| 분장표에 표시되는 업무의 최소 절차도 조회 | `GET /api/organization-division/procedure?taskId=...` |

다운로드 API의 매개변수는 `format=xlsx|pdf`, `departmentId`, `team`, `name`입니다. `departmentId`를 생략하면 관리자를 포함한 모든 역할에서 소속 부서를 적용합니다. 존재하는 다른 부서를 명시하면 모든 역할에서 그 부서의 분장표를 내려받습니다. `departmentId=all`은 관리자에게만 전체 부서를 뜻하며, 다른 역할에서는 기존 요청과의 호환을 위해 소속 부서로 해석합니다. `team=all`은 선택 부서의 모든 팀을 뜻합니다. 로그인하지 않으면 401, 잘못된 형식·존재하지 않는 부서·100자를 넘는 검색 조건에는 422를 반환합니다. 응답에는 첨부파일 이름, MIME 유형과 `no-store, private` 캐시 정책이 설정됩니다. 업무 본문·첨부파일은 이 API에 포함하지 않으며 기존 권한 검사를 유지합니다.

Vercel의 Node 런타임에서 `exceljs`, `pdfkit`으로 생성합니다. `next.config.ts`의 외부 서버 패키지 설정과 `public/fonts/Pretendard-Regular.otf`의 파일 추적 포함 설정을 유지해야 합니다.

## PDF 글꼴

정적 `Pretendard-Regular.otf`를 [Pretendard 공식 저장소](https://github.com/orioncactus/pretendard/tree/main/packages/pretendard/dist/public/static)에서 가져왔습니다. 라이선스는 `public/fonts/OFL.txt`에 있습니다. 시스템에 설치된 글꼴이나 외부 폰트 서버에 의존하지 않습니다. 앱용 가변 WOFF2 글꼴은 PDF 부분 임베딩에서 오류가 재현되어 PDF에는 정적 OTF를 사용합니다.

## 검증

```powershell
node --import tsx --test tests/organization-division.test.ts tests/organization-division-export.test.ts
```

모든 역할의 소속 부서 기본 조회·출력, 다른 부서 선택과 필터별 Excel·PDF 출력, 관리자 전체 선택, 민감한 본문·코드 제외, 타 부서 상세 수정·첨부 다운로드 차단, 승인된 현재 대행자만 표시, 업무 중복 방지, 실제 Excel 형식, 한국어 PDF와 긴 제목의 페이지 나눔, 다운로드 API 인증을 검증합니다. API 테스트는 `.qa-data`의 임시 저장소에서 실행하며 실제 Neon DB를 사용하지 않습니다. 화면의 기본 선택·부서 선택 활성화·타 부서 표시 검사는 `tests/search-focus.test.ts`에 포함됩니다.
