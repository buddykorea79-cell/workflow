# 2-A 조직·구성원 관리 검증

검증일: 2026-11-05. 프로토타입 기능 검증이며 실제 Neon 구성원·업무 데이터는 변경하지 않았습니다.

## 구현한 흐름

- 실제 연결된 **조직 · 구성원** 메뉴에서 기관 관리자가 부서와 구성원을 등록합니다.
- 구성원 이름 → **인사정보 변경**에서 부서·팀·역할·직위·연락처·공통업무 권한과 활성 상태를 변경합니다.
- 변경 사유는 필수이며 기존 사용자 ID는 유지됩니다. 비활성화는 계정 삭제가 아닙니다.
- 만료되었거나 비활성인 계정을 관리자가 재활성화하면 기존 만료 시각을 해제합니다.
- 남은 단위업무 소유·주담당·지원·검토·진행 회차·공통업무 총괄·배정 대기·대행·인수인계 책임을 표시합니다.
- 인사정보 변경 화면에서 인수인계 메뉴로 이동할 수 있습니다. 업무 소유권은 인사정보 변경만으로 자동 이동하지 않습니다.
- 최근 인사정보 변경의 사유, 전후 부서·팀·역할·상태, 변경자·시각을 같은 화면에서 확인합니다.

## 적용한 규칙

1. 기존 생성 권한을 유지하여 부서·구성원 등록과 인사정보 수정은 모두 기관 관리자만 허용합니다.
2. 전보 또는 활성 계정 비활성화는 남은 책임이 0건일 때만 허용합니다. 완료 회차의 역사적 수행자·검토자는 차단 대상이 아닙니다.
3. 팀·역할 변경은 현재 책임의 자격과 충돌하면 차단합니다. 개인 담당자에서 팀장으로 승진하는 것처럼 수행 자격이 유지되는 변경은 허용합니다.
4. 기존 부서의 마지막 활성 부서장·부서 담당자를 전보·비활성화·역할 해제하려면 먼저 후임을 등록해야 합니다. 새 빈 부서는 등록할 수 있으며 부서장·부서 담당자 배치를 안내합니다.
5. 관리자 본인의 비활성화 또는 관리자 권한 해제는 차단합니다. 마지막 활성 기관 관리자도 보호합니다.
6. 이메일은 공백·대소문자를 정규화하고 비활성 계정을 포함하여 중복을 검사합니다. 전화번호는 형식을 검사하며, 업무용 공용 전화번호는 중복을 허용합니다.
7. 기존 업무·회차·성과·인수인계·확정 업무분장 스냅샷은 변경하지 않습니다. 인사 변경 사유와 사용자 정보의 전후 값은 감사 기록에 남습니다.

## 자동 시험

다음 명령으로 신규 9건과 기존 16건, 총 **25건 통과**했습니다.

```powershell
node --import tsx --test tests/organization-management.test.ts tests/organization-demo.test.ts tests/workflow-v2.test.ts
```

| 결과 | 시나리오 |
| --- | --- |
| 통과 | 관리자 부서 등록 → 부서장·부서 담당자·직원 등록 |
| 통과 | 부서장·부서 담당자·팀장·일반직원의 생성 및 인사변경 거절 |
| 통과 | 비활성 계정 포함 이메일 중복, 잘못된 이메일·전화·부서·빈 사유 거절 |
| 통과 | 미배정 직원의 전보 → 비활성화 → 재활성화 및 기존 기록 불변 |
| 통과 | 주담당·단위업무·진행 회차가 남은 직원의 전보·비활성화 차단 |
| 통과 | 지원·검토·공통 총괄·예정 대행·팀/개인 배정 대기 책임 표시 |
| 통과 | 마지막 부서장·부서 담당자 보호, 후임 지정 뒤 처리 허용, 본인 관리자 잠금 방지 |
| 통과 | 수행 자격이 유지되는 승진 허용, 부적합 역할·팀 변경 차단 |
| 통과 | 완료 회차의 역사적 역할은 보존하면서 현재 인사 변경 허용 |

## 통합 화면 점검

격리 로컬 저장소에서 다음 항목을 확인했습니다. 실제 Neon의 인사정보는 변경하지 않았습니다.

- [x] 관리자 화면의 부서 등록·구성원 등록·인사정보 변경 버튼을 확인했다. 다른 역할의 변경 거절은 자동 테스트와 표시 조건 검토로 확인했다.
- [x] 신규 등록 직원이 조직 목록과 프로토타입 역할 선택 목록에 나타난다.
- [x] 인사 변경 폼에서 잔여 책임 4건, 전보 차단 사유, 인수인계 이동 버튼을 확인했다.
- [x] 미배정 직원의 부서 변경·비활성화·재활성화를 화면에서 완료했다.
- [x] 저장 후 다시 연 인사정보 변경 화면에서 변경 사유와 전후 부서가 보인다.
- [x] 390px 화면에서 가로 넘침 없이 폼에 접근하고 재활성화를 저장했다.

추가 통합 `npm test`는 **256개 전부 통과**했습니다. 잔여 역할 이관은 공통업무 총괄 2건을 후임에게 요청하고 해당 부서장으로 승인하여 이관 완료 및 요청·승인 로그까지 화면에서 확인했습니다. 새 부서 등록과 역할별 자격·권한·완료 기록 보존의 세부 조합은 격리 자동 테스트로 검증했습니다.

## 남은 범위

- 발령일을 예약하여 미래에 자동 적용하는 인사 일정은 포함하지 않습니다. 저장한 시점에 적용합니다.
- 직무대리 지정·인수 확인·반기 다부서 평가는 각각 로드맵의 후속 범위입니다.
- 실제 인증 계정 초대나 외부 인사시스템 동기화는 추가하지 않았습니다. 기존 프로토타입 역할 선택을 사용합니다.
- 새 환경변수나 DB 초기화는 필요하지 않습니다.
