## 현재 기능에 맞춰 보존할 세부 의미

- 2번은 페이지 설명과 중복 배치하지 않는다. 승인 대기 건수·요청 카드·승인 전 미접수 상태는 교육 설명이 아니다.
- 4번 상세의 실행 버튼명은 현재 화면에 맞는 **대상 부서 추가**를 사용한다.
- 5번의 제출기한은 H1에서 구분한 **중앙 제출기한**이다. 짧은 범례는 항상 보이고 산식·제외 상태는 자세히에 남긴다. 내부 회차 종료일 변경이 중앙 기한을 연장하지 않는다는 의미를 유지한다.
- 6·7번의 **남은 역할 정리**, **긴급 인사이동** 버튼은 고정 작업 영역으로 분리하여 도움말을 숨겨도 접근할 수 있게 한다. 기존 실행 권한 조건은 그대로 둔다.
- 8번의 부서 보관·이력 탭 설명은 승인 대기 문장으로 덮어쓰지 않는다. 승인 시 최신 진행 기록을 인계한다는 설명은 관련 상세에 보존한다.
- 9번 세부 안내의 탭 이름은 현재 실제 이름인 **성과**를 사용한다.
- 10번은 본인용 승인 문구를 적용하되 평가자는 직원이 비중과 성과를 제출해야 평가 가능하다는 역할별 제한을 유지한다.
- 11번은 이미 제출했다면 **제출 회수 후** 비중을 다시 설정한다는 복구 순서를 항상 남긴다.
- 12·13번의 제출 일시·평가자·평가일은 짧은 메타데이터로 보존한다. 평가 확정 후 수정 불가와 당시 스냅샷 보존을 변경하지 않는다.
- 14번은 **50점 만점의 단위별 점수 합산**이며 새로운 비례 환산 기능을 추가하지 않는다. 같은 지표·단위 합산, 비율·평균·점수 비합산, 이전 100점 평가 제외는 자세히에 보존한다.
- `짧은 1줄`은 문장 길이를 줄인다는 의미다. 모바일에서 경고를 nowrap·ellipsis·고정 높이로 잘라내지 않는다.

## 확정한 공통 UI 계약

```tsx
const help = useHelpControls(workspace.currentUser.id);

<HelpButton controls={help} label="개인업무 도움말 다시 보기" />
<HelpCallout
  controls={help}
  id="personal.hierarchy"
  summary="단위업무에 세부업무를 묶어 관리하세요."
>
  기존 상세 설명
</HelpCallout>
```

- `ui.tsx`에서 `useHelpControls`, `HelpButton`, `HelpCallout`을 제공한다.
- `HelpControls`: `userId`, `reopenToken`, `triggerRef`, `reopen`.
- `HelpCallout` 속성: `controls`, 고정 `id`, `summary`, 선택 `children`, 선택 `className`, 선택 `persistentSummary`.
- 첫 방문은 펼침이다. **사용자가 접었을 때만** collapsed를 기억하며 단순 방문으로 자동 접지 않는다.
- 사용자별 저장 키는 `ieum.help.<userId>.<id>`, 값은 `expanded | collapsed | dismissed`다. localStorage getter와 읽기·쓰기 모두 try/catch로 보호한다. 저장 실패 중에도 현재 화면의 접기·숨기기·다시 보기는 동작한다.
- 제목 옆 도움말 버튼은 같은 페이지의 교육 설명을 다시 펼친다. `다시 보지 않기`로 버튼이 사라지면 이 제목 도움말 버튼으로 포커스를 돌린다.
- 5번만 `persistentSummary`를 사용하여 숨김 상태에서도 실제 범례 문장과 `자세히`가 남는다. 다른 상태·경고를 이 속성으로 도움말 안에 편입하지 않는다.
- 페이지·폼 전체를 다시 마운트하지 않고 도움말 상태만 변경한다. 업무 저장·초안·권한 동작은 바꾸지 않는다.

2026-11-08 구현 반영: 공통 UI와 공통업무 4개, 개인업무 1개, 인수인계 2개, 성과·평가 교육 2개 및 상태·경고 5개를 적용했다. 도움말 저장·복구·포커스·범례·공통 권한 유지 신규 테스트 8개와 관련 기존 테스트 24개가 통과했고 마지막 타입 검사도 통과했다. 인수인계·성과 담당의 별도 관련 60개 테스트 통과 보고를 받았다. 기존 테스트 기대값은 바꾸지 않았다. 새 구성 테스트에서 관리자 승인권한을 잘못 가정한 부분은 관리자 요청 상세 / 실제 부서장 승인으로 fixture를 바로잡았다. 통합 전체 테스트·빌드와 1440×900/375px 실제 화면 검증은 root 기록에서 최종 확인한다.

통합 확인: 전체 660개 테스트·타입·빌드가 통과했다. 담당자의 네 화면에서 최초/숨김 목록 좌표를 실측했고 접힘·숨김 새로고침, 제목 다시 보기, 다른 계정의 설정 분리와 부서 담당자 1440/375 버튼 배치를 확인했다. 상세 수치·관찰 범위는 위 화면 확인 기록을 따른다.
