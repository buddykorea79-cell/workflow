# 세부업무 전용 화면 설계안 (D6)

설계 제안만 작성합니다. 기존 상세 팝업을 전용 화면으로 전환하는 코드는 이 작업에 포함하지 않습니다.

## 현재 구조

개인업무·대시보드·검색에서 TaskPanel을 열고, TaskEditor가 업무 기준과 절차 초안을 보유합니다. 일정·수행·성과·월별 실적은 별도 명령으로 저장합니다. 큰 팝업 안의 스크롤, 절차도 확대·확인창의 중첩, 화면 아래 저장 버튼과 모바일 높이 제약이 장시간 작업에 부담을 줍니다. 기존 미저장 보호와 중첩 모달 포커스·스크롤 복구는 유지해야 합니다.

## 화면 구성

1440px:
```text
← 원래 목록       세부업무 제목 · 기준 상태
┌────────────┬────────────────────────┬──────────────────┐
│ 업무 개요  │ 현재 탭 작업 본문      │ 담당자·업무 마감 │
│ 절차       │                        │ 회차·진행률      │
│ 일정·수행  │                        │ 다음 할 일       │
│ 성과 …     │                        │                  │
└────────────┴────────────────────────┴──────────────────┘
현재 저장 단위의 변경 요약                      [저장]
```

768px:
```text
← 목록       제목
업무 개요 | 절차 | 일정·수행 | 성과 | …
담당·업무 마감·진행률                       [더 보기]
현재 탭 본문
변경 요약                                  [저장]
```

375px:
```text
← 목록        제목
가로 이동 탭 목록
마감·진행 요약 [펼치기]
본문 한 열
변경 요약
[현재 영역 저장]  (기기 안전 영역 확보)
```

## 저장·초안

- 업무 기준과 절차는 현재처럼 하나의 저장 단위로 유지합니다.
- 일정, 절차 수행, 성과, 월별 실적은 각각의 저장 버튼과 성공 상태를 보여줍니다. 여러 명령의 부분 실패를 숨기는 '모두 저장'은 도입하지 않습니다.
- 탭 초안은 업무 ID에 속한 상세 컨테이너가 유지합니다. 탭 전환으로 초안이 보존되면 확인창을 띄우지 않고, 실제 화면 이탈·업무 교체·역할 변경에는 미저장 보호를 적용합니다.
- 저장 중 새로 입력한 값은 응답으로 덮어쓰지 않습니다. 현재 저장 대상 스냅샷과 이후 초안을 구분합니다.
- 하단 저장 바에는 현재 저장할 영역의 이름을 명시하고, 본문 마지막 콘텐츠를 가리지 않도록 여백을 확보합니다.

## 경로와 복귀

M10의 `#<view>/task/<id>/<tab>` 규칙을 재사용합니다. 대시보드·검색·알림·부서 업무분장에서 같은 상세 경로로 진입합니다. 원래 목록의 필터·검색어·스크롤은 복귀 상태로 보존하고, 직접 링크·새로고침 진입은 경로의 view에 해당하는 목록으로 돌아갑니다. 접근 불가 업무는 서버의 기존 권한 판단과 안내를 유지합니다.

## 전환 순서와 위험

1. 딥링크와 뒤로가기·미저장 보호 검증.
2. 상세 본문을 모달 껍질에서 분리하되 저장 명령은 유지.
3. 기능 플래그로 모달·페이지를 병행해 1440/768/375px와 모든 역할을 검증.
4. 링크 공유·첨부·절차도·인수인계·평가 회귀 확인 후 기본 표현 전환.
5. 충분히 관찰한 뒤 이전 모달 경로 제거. 그 전에는 플래그를 되돌려 복구.

주요 위험은 초안의 마운트 수명 변경, 뒤로가기의 중복 기록, 팝업용 CSS·포커스 트랩의 잔존, 제출 중 이탈 후 결과 반영입니다.

## 결정할 사항

전용 화면을 기본으로 사용할지, 탭별 초안을 페이지를 벗어난 뒤에도 유지할지, 우측 요약의 범위, 기존 업무 기준·절차 통합 저장을 유지할지를 전환 전에 결정해야 합니다.
