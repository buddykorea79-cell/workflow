# 온이음 개선 체크리스트와 단계별 실행 프롬프트

기준일: 2026-11-05

이 문서는 실제 업무를 가정한 기능 검토를 바탕으로 작성한 **프로토타입 개선 계획**입니다. 운영 전환, 기관 인증 도입, 유료 서비스 가입, 실제 데이터 초기화는 이 계획의 전제 조건이 아닙니다.

## 사용 방법

1. 먼저 아래 **1차 개선**의 검증 상태를 확인합니다. 상세 시험 결과는 [1차 개선 QA](QA-phase1-improvements.md)에 기록합니다.
2. 이후에는 `2-B 미완료 항목 → 2-C → 3-A …` 순서로 **프롬프트 하나씩** 실행합니다. 한 번에 다음 단계 전체를 요청할 필요는 없습니다.
3. 각 프롬프트를 새 대화에 붙여 넣어도 되지만, 같은 프로젝트 `D:\Workflow-Project`를 열어 둡니다.
4. 완료할 때에는 구현뿐 아니라 해당 항목의 완료 기준을 검증하고 체크합니다. 해결하지 않은 항목은 완료로 표시하지 않습니다.
5. 실제 사용자의 업무 규칙이 더 구체화되면 그 지시가 이 문서의 제안보다 우선합니다.

아래 프롬프트는 모두 현재 저장소의 `AGENTS.md`와 관련 Next.js 로컬 문서를 먼저 읽고 작업하도록 구성했습니다. 실제 Neon DB·첨부파일은 보존하고, 회귀 검증에는 메모리 데이터 또는 격리된 테스트 저장소를 사용합니다. 비밀 환경변수는 출력하거나 문서에 옮기지 않습니다.

### 현재 공통업무 권한과 배포 방식

현재 역할은 **업무 담당자·팀장·부서 담당자·부서장·관리자** 5개입니다. 별도의 공통업무 담당 권한은 없으며, 부서장을 제외한 활성 구성원이 **공통업무 · 지시사항**에서 세부업무를 작성할 수 있습니다. 작성 부서장의 승인 후에만 지정 부서에 등록되며, 대상 부서의 부서 담당자 → 팀장 → 업무 담당자 순서로 배부·배정합니다. 반려 사유 확인·보완 재요청과 추가 부서 배포 승인도 같은 메뉴에서 처리합니다. 구현 범위와 최신 검증 기록은 [공통업무 배포 승인 QA](QA-common-publication.md)를 확인합니다.

작성 부서장의 **배포 승인**은 아래 `3-C`의 **확정된 대상 부서에서 변경분만 배정 승인**과 별개입니다. 확정 부서에 새 업무를 접수할 수 있지만, 배정·내 단위업무 등록은 현재 재작성 허용 절차를 따릅니다. 이 변경으로 `3-C`를 완료한 것은 아닙니다. 아래 과거 검증 수치와 완료 기록은 당시 결과를 보존합니다.

### 1차 적용 뒤에도 남는 제한

- **공통업무 접수와 배정은 다릅니다.** 확정된 부서에 접수된 새 업무의 배정은 아직 재작성 허용 흐름을 따릅니다. 변경분만 승인하는 기능은 `3-C`에서 다룹니다.
- **이전 형식의 인수인계 승인 대기 요청**에는 업무 정의 비교 정보가 없습니다. 이런 요청에서 작성 후 변경이 발생했다면, 최신 내용으로 취소·재요청해야 할 수 있습니다. 새 요청부터 진도 변경과 업무 기준 변경을 구분합니다.
- 주담당 업무 이관과 별도로 **남은 역할 정리**에서 지원·검토·공통업무 총괄·배정 대기 역할을 선택해 부서장 승인을 받을 수 있습니다. 대행 권한 해제도 포함합니다. 직무대리·인수 확인은 `2-B`의 후속 대상입니다.
- 이전 담당자의 기존 성과 보완과 제출 배점 보존을 먼저 해결합니다. **한 사람이 같은 반기에 여러 부서에서 근무한 실적을 나눠 제출·평가하는 전체 모델**은 `2-C`에서 확장합니다.
- 선택 절차 생략, 검토 반려·재제출, 다음 회차 병행, 자동 알림·초안 복구는 후속 단계에 포함됩니다.

```text
이미 존재하는 생성 API를 활용하고, 구형 화면에만 남은 기능을 중복 구현하지 마.

소속만 바뀌었다고 업무 소유권을 자동 변경하지 말고 인수인계 흐름과 연결해 줘.
관리자·부서담당자·일반 직원의 권한을 기존 범위에 맞게 검증해.
실제 Neon 데이터를 초기화하지 말고 격리 데이터로 등록→전보→비활성화와 권한 회귀를 시험해.
완료 기준과 결과를 QA에 기록하고 이 문서의 2-A 체크를 갱신해 줘.
```

### 2-B. 인수인계의 잔여 역할·직무대리·인수 확인

- [x] 주담당 외 지원담당·검토자·공통업무 총괄·배정 대기 책임·대행 역할을 점검한다. 현재 업무 기준과 마지막 확정 기준, 진행 회차를 각각 확인한다.
- [x] 역할별 후임과 변경 사유를 정하고 부서장 승인 후 적용한다. 대행은 해제만 하며 새 권한을 자동 부여하지 않는다.
- [x] 승인 후에도 완료 회차의 수행자·검토자 기록은 바꾸지 않는다.
- [ ] 부서장 부재는 공식 직무대리 지정과 유효기간으로 처리한다.
- [ ] 배정 완료와 인수자의 자료 확인·미결 사항 확인을 구분한다.
- [x] 선택한 지원·검토 역할 정리 후 해당 접근이 제거되며, 본인의 인수인계 기록은 유지한다. 전보 전 전체 잔여 책임 검사와 함께 사용한다.

**현재 반영 범위:** 검토 후임은 부서장·부서담당자·팀장, 지원 후임은 업무 담당자·팀장·부서담당자, 공통 총괄 후임은 해당 부서의 활성 업무 담당자·팀장·부서 담당자·관리자입니다. 별도의 공통업무 담당 권한은 필요하지 않습니다. 등록 전 팀장·담당자는 기존 배정 팀 안에서 선택합니다. 서로 자격이 다른 역할은 나누어 요청합니다. 지원 역할의 후임 없는 단순 해제, 예정 발령 자동 적용은 아직 제공하지 않습니다. 이미 등록된 공통업무의 담당자 변경은 기존 주담당 인수인계에서 처리합니다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 2-B에서 남은 직무대리·인수 확인 항목을 구현해 줘. 2-A와 현재 남은 역할 정리 기능을 먼저 확인해.
이미 구현한 지원·검토·공통업무 총괄·배정 대기 역할 이관 및 대행 해제의 부서장 승인·자격 재검증·중복 방지 규칙을 유지해.
긴급 보관→전체 또는 일부 배정→부서장 승인이라는 기존 흐름과 완료 기록 보존 원칙을 유지해.
부서장 부재 시에는 기간과 지정 사유를 남기는 공식 직무대리 방식으로 승인할 수 있게 해 줘. 관리자라는 이유만으로 승인 검사를 우회시키지 마.
배정 승인은 즉시 반영하되, 인수자의 자료 확인·미결 사항·다음 마감 확인은 별도로 기록해 줘.
인사 변경 뒤 남는 이전 부서 접근과 본인 이력 조회 권한을 함께 검증해.
실제 DB 변경 없이 격리 시나리오로 정상 승인·부재·잘못된 대리 승인·누락 역할을 시험하고 QA와 로드맵을 갱신해 줘.
```

### 2-C. 반기 중 여러 부서에서 근무한 사람의 성과

- [ ] 개인·반기·소속 기간별로 과거 실적을 구분한다.
- [ ] 이전 부서의 평가 권한과 새 부서의 평가 권한이 섞이지 않는다.
- [ ] 같은 실적의 중복 제출·중복 합산을 방지한다.
- [ ] 기존 한 부서 배점·평가 데이터가 계속 조회된다.
- [ ] 확정된 과거 평가를 덮어쓰지 않고 정정 이력을 남긴다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 2-C를 진행해 줘. 1차의 원작성자 성과 보완과 제출 배점 보존 기능을 이어서 확장해.
같은 반기에 부서를 옮긴 사람이 이전 부서와 새 부서 실적을 각각 제출하고, 각 부서장이 자기 소속 기간 실적만 평가할 수 있게 해 줘.
현재 한 사람·한 반기에 하나인 배점 모델과 기존 데이터의 호환성을 먼저 검토해.
중복 실적·중복 점수 합산을 막고, 이미 확정된 평가와 작성자 기록을 보존해 줘.
기간별 점수를 어떤 비율로 합산할지는 기관 정책이므로 임의 공식을 확정하지 말고, 우선 부서별 결과를 분리해 보여줘.
기존 부서장·새 부서장·전출자·후임자의 접근을 격리 테스트로 확인하고 화면에서 실제 제출·평가를 끝낼 수 있게 해 줘.
검증 결과와 남은 정책 선택 사항을 QA 및 로드맵에 기록해 줘.
```

## 3단계 — 검토 보완·선택 절차·추가 업무 처리

### 3-A. 보완 요청과 선택 절차 생략

- [ ] 검토자가 보완 요청을 보내고 담당자가 보완·재제출할 수 있다.
- [ ] 기존 완료 결과를 지우지 않고 보완 회차·사유·검토 기록을 남긴다.
- [ ] 선택 절차는 사유를 남겨 생략할 수 있다.
- [ ] 필수 절차와 필수 검토는 생략으로 우회할 수 없다.
- [ ] 선행 관계·진행률·사이클 완료·공통업무 현황이 새 상태를 일관되게 반영한다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 3-A를 구현해 줘.
업무 수행 검토에 보완 요청→보완 기록→재제출→재검토 흐름을 추가해 줘. 성과평가 반려와 업무 수행 보완을 구분해.
완료된 단계의 원래 결과·체크·작성자·시각은 보존하고 보완 내용을 새 기록으로 연결해 줘.
required:false인 선택 절차에는 해당 없음/생략과 사유를 기록할 수 있게 하고, 필수 절차·필수 검토는 생략할 수 없게 해 줘.
선행 관계, 진행률, 업무 사이클 완료, 공통업무 현황이 같은 규칙으로 상태를 계산하도록 맞춰 줘.
실제 DB를 수정하지 않는 테스트로 보완 반복·생략·권한 위반·순환/의존 관계·다음 회차 전환을 확인해.
담당자와 검토자 화면을 확인하고 QA 및 로드맵을 갱신해 줘.
```

### 3-B. 다음 회차 예약과 병행 수행

- [ ] 기존 회차 검토 중에도 다음 회차 일정을 준비할 수 있다.
- [ ] 업무마다 순차 진행과 병행 허용을 구분한다.
- [ ] ‘현재 회차’ 하나에만 의존하는 화면을 회차 선택에 맞게 정리한다.
- [ ] 회차별 담당자·기준 버전·일정·결과·완료 이력이 섞이지 않는다.
- [ ] 반복 일정의 휴일 처리 규칙을 명시하고 자동으로 임의 변경하지 않는다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 3-B를 구현해 줘. 3-A의 상태 모델을 먼저 확인해.
전월 검토가 지연되어도 다음 달 회차의 일정을 예약할 수 있게 해 줘.
기존 순차 사이클은 기본값으로 유지하고, 업무별로 허용한 경우만 여러 회차를 병행 실행하게 해 줘.
최신 회차 하나만 현재 업무로 간주하는 코드와 화면을 찾아 회차 선택, 일정, 공통업무 현황이 섞이지 않게 수정해.
각 회차의 담당자·기준 버전·중앙 기한·수행 기록은 독립적으로 보존해 줘.
휴일 자동 이동은 정책이 없으면 적용하지 말고 명확한 안내를 제공해.
이전 회차 인수인계와 다음 회차 시작이 겹치는 격리 시나리오까지 검증하고 QA 및 로드맵을 갱신해 줘.
```

### 3-C. 확정된 부서의 신규 공통업무 추가 배정

- [ ] 확정 후 접수된 공통업무를 기존 업무분장 전체 재개방 없이 배정할 수 있다.
- [ ] 변경분의 담당자·검토자·단위업무 연결만 부서장이 승인한다.
- [ ] 승인 전에는 기존 확정 업무분장과 책임이 유지된다.
- [ ] 변경분 승인과 기존 확정본의 관계를 이력에서 확인할 수 있다.
- [ ] 중앙 제출기한 초과는 담당자의 내부 일정 수정으로 숨겨지지 않는다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 3-C를 구현해 줘.
1차에서 허용한 확정 부서의 공통업무 접수를 이어서, 신규 업무의 추가 배정만 별도로 승인할 수 있게 해 줘.
기존 업무분장 전체를 재작성 상태로 열지 않고, 새 업무의 팀·담당자·검토자·단위업무 연결을 변경안으로 제출해 해당 부서장이 승인하게 해 줘.
승인 전 기존 책임과 확정 스냅샷을 유지하고, 승인 후에는 변경분과 승인자를 이력으로 연결해 줘.
중앙 제출기한과 내부 수행 일정을 구분하는 1차 규칙을 유지해.
반려·재요청·중복 배정·인사이동 중 승인·미권한 승인을 격리 테스트하고, 각 역할의 접수부터 수행까지 화면을 확인해.
완료 기준과 QA, 로드맵 체크를 갱신해 줘.
```

## 4단계 — 여러 사람의 동시 사용과 작성 내용 보호

### 4-A. 업무별 저장 충돌 처리

- [ ] 다른 부서의 알림 읽음 때문에 업무 저장이 실패하지 않는다.
- [ ] 같은 업무의 충돌은 변경한 항목과 최신 값을 보여준다.
- [ ] 다시 저장할 때 다른 사람의 수정 내용을 조용히 덮어쓰지 않는다.
- [ ] 인수인계처럼 여러 객체를 바꾸는 명령의 원자성은 유지한다.
- [ ] 중복 요청의 재시도는 한 번만 반영된다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 4-A를 구현해 줘.
워크스페이스 전체 revision 때문에 무관한 작업끼리 충돌하는 문제를 업무·회차·요청별 충돌 검사로 개선해 줘.
알림 읽음과 개인 UI 상태가 다른 사람의 업무 저장을 무효화하지 않게 해.
같은 항목을 동시에 수정했을 때에는 최신 값과 내 입력을 비교해 선택할 수 있게 하고, 자동 재시도로 타인의 변경을 덮어쓰지 마.
다중 객체를 변경하는 승인·인수인계의 원자성 및 requestId 중복 방지는 유지해 줘.
실제 DB로 부하를 주지 말고 격리 환경에서 서로 다른 업무/같은 업무/재시도/인수인계 동시 수정 시나리오를 검증해.
QA와 로드맵을 갱신하고 JSONB 저장 구조의 추가 확장이 필요한지는 실제 측정 근거가 있을 때만 별도로 제안해 줘.
```

### 4-B. 승인·배정·마감 알림과 화면 갱신

- [ ] 다른 사람이 배정·승인한 내용이 열린 화면에도 반영된다.
- [ ] 갱신이 작성 중인 입력값과 선택한 회차를 지우지 않는다.
- [ ] 승인 대기·마감 임박·지연 알림이 담당 역할에 맞게 전달된다.
- [ ] 중복 알림과 완료 후 불필요한 알림을 방지한다.
- [ ] 한국 시간 기준 날짜와 앱 안 알림의 범위를 명확히 한다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 4-B를 구현해 줘. 4-A의 저장 충돌 처리와 함께 검토해.
프로토타입 규모에 맞는 화면 갱신 방법을 적용해 다른 사람의 배정·승인·진행 변경을 확인할 수 있게 해 줘.
화면 갱신 때문에 작성 중인 내용이나 선택 회차가 바뀌지 않도록 보호해.
앱 안에서 승인 대기·마감 임박·지연 알림을 담당자·지원자·검토자 역할에 맞게 제공하고 중복을 방지해.
중앙 제출기한과 한국 시간 기준 날짜를 사용하고 완료한 업무에는 불필요한 마감 알림을 보내지 마.
외부 이메일·문자·메신저 전송은 이번 범위에 추가하지 마.
격리된 두 사용자 화면과 날짜 경계 시나리오를 검증하고 QA 및 로드맵을 갱신해 줘.
```

### 4-C. 초안 저장·복구와 화면 이탈 보호

- [ ] 긴 업무 설명·근거·AI 초안·성과 입력을 임시 저장할 수 있다.
- [ ] 새로고침·닫기·역할 전환 전에 미저장 변경을 안내한다.
- [ ] 로그인 사용자·업무·회차가 다른 초안을 섞어 복구하지 않는다.
- [ ] 서버의 최신 내용과 충돌하면 비교 후 복구한다.
- [ ] 자동 임시저장이 실제 제출·승인으로 이어지지 않는다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 4-C를 구현해 줘.
업무 설명, 관련 근거, AI 절차 초안, 일정 및 성과의 긴 입력 내용을 임시 저장하고 복구할 수 있게 해 줘.
모달 닫기, 화면 이동, 새로고침, 역할 전환 시 저장하지 않은 변경을 안내해.
초안은 사용자·업무·회차별로 분리하고, 서버의 새 버전과 다른 경우 덮어쓰지 말고 비교 후 복구하게 해 줘.
자동 저장과 실제 업무 저장·제출·승인을 화면에서 구분해.
브라우저 저장 방식과 삭제 시점도 명시하고 다른 사용자의 초안이 노출되지 않도록 검증해.
파일 업로드나 화면 갱신 중 입력이 보존되는지도 시험한 뒤 QA 및 로드맵을 갱신해 줘.
```

## 5단계 — 문서·근거·AI 결과의 신뢰도와 활용성

### 5-A. 문서 추출 범위와 형식 지원

- [ ] 저장 성공·본문 추출 성공·부분 추출·수기 입력 필요를 구분한다.
- [ ] 우선순위를 정해 HWPX·DOCX 등 실제 업무 문서 형식을 추가한다.
- [ ] 미지원 HWP·스캔 자료를 분석 완료로 표시하지 않는다.
- [ ] 긴 문서는 조항·페이지를 골라 분석하고 누락 범위를 확인한다.
- [ ] OCR을 추가할 경우 처리 결과와 원문을 대조할 수 있다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 5-A를 구현해 줘.
먼저 파일 저장 상태와 본문 추출 상태를 구분하고, 부분 추출·누락 페이지·길이 제한을 화면에 지속적으로 표시해 줘.
현재 의존성과 실행 환경을 확인한 뒤 HWPX와 DOCX 본문 추출부터 추가해. HWP·이미지·스캔 PDF는 실제 지원한 범위만 표시해.
긴 문서는 앞부분을 잘라 쓰는 것에만 의존하지 않고 사용자가 분석할 조항·페이지·본문을 선택하게 해 줘.
OCR은 기존 환경에서 가능한 범위를 확인하고, 새 유료 서비스 연결이 필요하면 그 연결을 완료한 것처럼 구현하지 말고 수기 대체 흐름을 유지해.
표·한글 문서·텍스트와 스캔 페이지가 섞인 PDF·추출 실패를 격리 자료로 검증해.
지원 형식 표와 QA 및 로드맵을 갱신해 줘.
```

### 5-B. 근거 버전과 절차의 연결·AI 검토 기록

- [ ] 근거의 개정 버전·시행일·확인 상태를 기록한다.
- [ ] 절차 단계가 어떤 근거의 어떤 버전을 사용했는지 연결한다.
- [ ] 근거 변경 시 영향을 받는 절차에 재검토 표시가 생긴다.
- [ ] AI 인용의 존재·위치·의미 검토를 구분한다.
- [ ] 단계별 원문 대조, 검토자·검토일·적용 기록을 남긴다.
- [ ] 기존 자료함과 관련 근거의 AI 외부 전송 허용 정책을 일치시킨다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 5-B를 구현해 줘.
근거의 개정 버전·시행일·검증 상태와 절차 단계의 근거 ID/버전을 구조적으로 연결해 줘.
근거가 바뀌면 기존 절차를 자동으로 확정하지 말고 영향을 받는 단계에 재검토 필요를 표시해.
AI의 인용문 존재 확인과 법령·지침의 의미 판단을 구분하고, 단계별 원문 대조 및 검토자·검토일·적용 기록을 남겨 줘.
가짜 페이지 위치, 원문과 반대되는 절차, 필수 조항 누락 사례를 검증 자료로 사용해. AI가 타당성을 완벽히 보장한다는 표현은 쓰지 마.
기존 자료함과 새 관련 근거의 자료 분류·AI 외부 전송 허용 규칙도 통일하고, 실제 내부 자료를 자동 전송하는 시험은 하지 마.
현재 BizRouter 구조화 응답·순환 관계·사용자 적용 확인 보호를 유지하면서 QA 및 로드맵을 갱신해 줘.
```

### 5-C. 산출물 최종본·검색·첨부 확인 절차

- [ ] 산출물을 업무·회차·절차에 연결한다.
- [ ] 문서 버전과 최종본, 교체 이력을 표시한다.
- [ ] 업무·근거·문서 제목과 지원되는 본문을 권한 범위 안에서 검색한다.
- [ ] 파일 허용 대기와 담당 관리자의 확인 작업을 명확히 보여준다.
- [ ] 이전 회차나 인수인계 자료를 찾아 내려받는 흐름을 검증한다.

**복사할 프롬프트**

```text
온이음 개선 로드맵의 5-C를 구현해 줘.
산출물에 업무·회차·절차 연결, 문서 버전, 최종본 표시, 교체 이력을 추가해 줘.
현재 업무 단위 첨부 데이터는 잃지 않고 연결 미지정 자료로 계속 조회할 수 있게 해.
업무·근거·문서 제목과 지원되는 본문을 검색하되 현재 사용자의 열람 권한을 검색 결과에도 적용해.
```
