# 전체·일부 업무대행

## 사용 순서

1. **업무대행 → 업무대행 요청**을 누른다. 세부업무의 **대행 승인 요청**에서도 같은 선택표를 이용한다.
2. 업무 담당자는 본인 업무를, 부서 담당자는 같은 부서의 원담당자를 선택한다. 관리자는 관리 대상 원담당자를 선택할 수 있다.
3. 업무분장표 형식의 체크박스에서 **전체 업무**, **단위업무 전체**, **개별 세부업무**를 선택한다. 일부를 선택한 상위 체크박스는 부분 선택 상태로 표시한다.
4. 같은 부서의 업무대행자, 시작일·종료일과 사유를 지정하고 요청한다.
5. 원담당자 부서장은 요청 상세의 업무 목록을 검토하여 함께 승인하거나 반려한다.
6. 승인된 기간에 대행자의 개인업무 **업무대행** 묶음에 선택한 원본 업무가 표시된다.

한 요청은 한 원담당자의 같은 부서 업무 1~300건을 포함한다. 현재 선택한 세부업무만 고정하여 요청하며 나중에 새로 등록한 업무는 자동으로 포함하지 않는다. 원본 단위·세부업무를 복제하거나 소유자를 변경하지 않는다.

## 승인·변경 처리

선택한 업무 중 하나라도 원담당자·업무 기준·대행 기간·대행자 자격이 변경되었거나 중복 대행 기간과 충돌하면 전체 요청 또는 승인이 실패한다. 다른 업무만 일부 승인되는 일은 없다. 각 업무의 요청·승인·처리 이력과 전체 요청의 업무 ID를 함께 남긴다.

일괄 요청은 일괄 취소·종료할 수 있다. 인사이동 처리에서 일부 업무가 이미 종료되었다면 그 종료 기록은 보존하고 남은 승인 대기 업무를 취소하거나 대행 중인 업무를 종료한다. 일부가 종료된 요청을 그대로 일괄 승인할 수는 없으므로 남은 요청을 취소한 뒤 범위를 다시 선택한다.

## API 계약

- `delegation.requestBatch`: `{ fromId, taskIds, toId, startsAt, endsAt, reason }`
- 기존 `delegation.approve/reject/cancel/revoke`: 단일 `{ delegationId, reason }` 또는 그룹 `{ batchId, reason }`
- 일괄 요청에 속한 개별 `delegationId`로 처리해도 그룹 전체에 적용한다. 단일 ID 호출로 일괄 승인 검사를 우회할 수 없다.
- 기존 단일 요청과 신규 업무 등록 시 단일 대행 지정은 호환된다.
